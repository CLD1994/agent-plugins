# i-am-yuna 调度规范

本技能供负责向下委派或管理下级 agent 的角色使用。先满足正确性、用户授权和与风险相称的安全措施，再选择从开始调查到最终验收的预计总成本最低的路线。总成本包括调查、执行、重试、评审和返工，不能只按单次调用价格判断；模型层级的长期经验成本比例保留为 `1:10:30`，这是结合实际模型价格统计得出的长期经验估算，用来比较同一任务的完整路线。

## 角色、加载和权限

本技能的适用角色和职责如下；加载时机由当前作用域的项目入口规定：

- 根级 Main Agent 位于整棵 agent 树的顶层，负责全局用户意图、上下文切片、调度和最终采用。
- 当前层级调度者负责一个任务及其直接下级；它可以是根级 Main，也可以是嵌套 subagent，并在自己的子树内承担同样的调度职责。
- 只完成父任务且不管理下级的纯执行者不承担本规范的调度职责，把结果、阻塞和停止报告交给直接父级。

嵌套调度者继承父任务给出的目标、授权、范围、起始基线和共享约束。加载本技能不会扩大权限；需要改变父任务的行为、授权、范围、起始基线或验收条件时，停止相关工作并向父级报告。只有根级 Main Agent 处理需要用户作出的决定、全局采用、全局合并和不可逆清理，除非用户或父任务在任务单或补充中明确写出授权来源、命名对象、允许的结果或动作、必须保持的不变量和执行条件，并将决定限制在该窄范围内；任何下级都不能从该授权再向外推导更大权限。

本技能的规则同时适用于根级和嵌套调度。凡规则写“当前层级调度者”，由拥有该任务范围的调度者执行；凡规则写“根级 Main”，只由根级处理。经验不能替代当前任务规格、父级授权或用户决定。

## 经验文件

经验文件只记录有证据的调度、切分和上下文压缩经验，不能替代或修改当前任务规格、用户授权、权限边界或验收条件。文件路径只接受用户消息或当前作用域的项目约定提供的值；按需读取其中与当前任务匹配的条目。未声明路径时不搜索、猜测或创建经验文件，也不因此阻塞。

## 建立调度依据

根级 Main 先把用户意图固定为可观察行为、授权边界、必要约束、验收条件和起始基线。嵌套调度者把父任务中已经固定的这些内容作为只读输入，并为自己的子树记录更窄的任务边界。行为、授权、风险或规格没有唯一答案时，由根级 Main 决定或询问用户；嵌套调度者向父级报告，不自行改变这些条件。

然后由根级 Main 依据当前 Harness 明确提供的模型和思考强度选项，分别建立并记录两层映射：模型层级到模型的映射，以及所选模型到思考强度的映射。只对 Harness 实际暴露的选项提出映射；两层映射及其依据、预期成本差异和不确定性只写入当前会话或任务调度记录，不写项目上下文。首次建立映射、可用模型或思考强度选项发生变化，或无法可靠映射时，由根级 Main 请求用户确认；嵌套调度者继承父级已经确认的映射，不自行重定义，缺少或无法可靠映射时向父级报告。不要在仓库中硬编码具体模型名或厂商特有的思考强度名称。

|模型层级|经验成本比例|默认用途|
|-|-:|-|
|执行级|1|从事边界稳定的执行、事实核对、测试和批量工作|
|思考级|10|从事需要独立语义判断或复杂因果推理的工作|
|顾问级|30|在规定升级后提供分析；在根级 Main 已获得用户批准，或父任务按本技能授权规则明确获准的匿名比较中，按任务单另行记录为执行角色时承担一条批准的完整路线|

工作角色与模型层级是两个维度，必须分别记录。例如，执行级模型可以做事实核对，思考级模型可以做独立评审；在根级 Main 已获得用户批准，或父任务按本技能授权规则明确获准的匿名比较中，顾问级模型按任务单另行记录为执行角色时，生成候选、接受独立评审并按普通执行结果累计有效失败。顾问分析角色只分析，不作决定或实施，也不产生候选或执行失败。

|工作角色|负责的结果|
|-|-|
|执行|写出已批准范围内的主体产物并提供验证证据|
|事实核对|只读地定位事实、入口、依赖和原始位置|
|独立评审|判断候选是否满足已固定的契约，不实施候选|
|整合|合并已采用的切片并做端到端验证|
|顾问分析|只分析当前固定任务和指定结论，识别风险、固定证据并报告；以顾问角色不作决定或实施，另行派执行任务时按执行角色重新记录|

根级 Main 负责用户意图、全局切片、角色与层级、并行和隔离、全局调度记录、候选取舍、最终采用与合并和不可逆清理。嵌套调度者只负责继承范围内的切片、角色与层级、局部记录、下级结果和子树接缝；不得覆盖父级共享约束或替父级采用结果。每个调度者都接收自己下级的结果和评审结论，判断理由是否成立、结论是否冲突、覆盖是否完整；需要更多事实时派事实核对，需要新的独立判断时派评审。任何层级都不重做已交给下级的全库调查或完整评审。每个 subagent 自己写本切片的计划、checkpoint、结果、评审报告或清理清单；完成主体工作的 agent 直接写主体产物，不由另一个 agent 转写。

## 决定当前层级直接处理还是委派

完整且能独立验收的执行计划是委派依据，不是当前层级调度者亲自执行的许可。仓库搜索、事实调查、实现、测试、普通提交和批量处理默认交给执行级 subagent。

当前层级调度者只有同时满足以下条件，才可直接完成局部收尾：

1. 动作自然产生于该调度者自己负责的需求判断、调度决定或结果整合；
2. 正确改法能由该调度者已持有的上下文唯一推出；
3. 不需要搜索、比较或逐项检查其他对象；
4. 只处理一个局部责任，不构成可独立交付的执行任务；
5. 验证方式已经确定；
6. 中间结果只需判断成功或失败；一旦出现意外，停止扩大范围并重新委派或向父级报告。

|情况|处理方式|
|-|-|
|用户行为、授权或风险边界需要决定|根级 Main 决定或询问用户；只有按上述规则明确授权的调度者才能在命名对象、允许结果、不变量和条件内处理|
|符合全部局部收尾条件|当前层级调度者可以直接完成|
|已经形成完整且可独立验收的执行计划|交给执行级 subagent|
|还需搜索、比较、逐项分类或解释仓库事实|先交给执行级事实核对 subagent|

例如，调度者整合结论时发现同一位置有唯一确定的错字，可以直接修正并运行已知检查；已确定要改五个文件及其验证方式，仍是独立执行任务；删除清单已经由独立调查固定且无歧义时，只有根级 Main 或按任务单/补充明确写出授权来源、命名资源、允许动作、必须保持的不变量和执行条件的调度者可以最终删除，但判断哪些本地分支过时必须先委派调查。

## 切片、上下文和任务单

按可独立验收的结果与责任边界切分，不按文件数切分。每个切片只收到完成它所需的紧密相关权威来源。当前层级调度者缺少入口或依赖事实时，先派只读事实核对者制作保留原始位置的来源索引。

相关切片共享同一份最小约束；执行者不读取其他切片的计划、checkpoint、中间结果或推理。当前层级调度者通知本层受影响切片；父级共享约束在嵌套层是只读输入，嵌套调度者不能自行修改。多个可分别验收的切片可以并行；多个写入者使用各自的隔离 worktree。共同组成同一用户流程、状态机或协议的切片，要另设整合或接缝任务验证组合行为。

每次委派都先由当前层级调度者写任务单。任务单至少给出：

- 具体交付结果；
- 固定起始基线和当前任务说明版本；
- 已确认的行为、授权边界和共享约束，以及初始共享约束版本或“无共享约束”；
- 允许读取的权威路径；
- 允许修改的范围；
- 每项验收条件和已知验证方式；
- 必须停止并报告的情况；
- checkpoint、结果、评审或提交的交付位置；
- 已批准的实现计划；未被规格固定的模块、接口、文件和提交安排明确标为建议。

subagent 可以自行决定不改变可观察行为的内部实现细节。遇到必须改变行为、授权或既定范围，权威来源冲突或缺少必要行为，现有条件不能满足验收，或只有违反安全规则、项目规则或明确禁止的捷径才能继续时，停止相关工作并向直接父级报告事实。

调度记录、任务单、补充说明、checkpoint、报告和恢复状态的唯一规则与模板见 [调度记录、补充说明与恢复](references/dispatch-records.md)。仅当前环境为 Codex Harness，且当前层级调度者要创建、联系、恢复、评审、整合或等待自己的 subagent 时，读取 [Codex Harness 交互](references/codex-subagent.md)；其他 Harness 只遵循自身提供的交互说明，本技能不推导其工具调用。适配文档只补充交互接口，不改变本文件的角色、权限和调度规则。

## 运行、结果和升级

每个新的、任务说明稳定的切片从执行级开始。用户明确指定模型，或用户已经批准匿名比较，是仅有的默认起点例外；嵌套层还必须有父任务的明确授权。当前层级调度者可以向原 subagent 发送按顺序编号的补充说明；补充不会自动换人、强制写 checkpoint 或清零失败记录。版本、处置和失败连续性的规则见 [调度记录、补充说明与恢复](references/dispatch-records.md)。

一次执行只能归入以下一种结果：

|结果|判定条件|后续处理|
|-|-|-|
|已完成并通过|执行者声明完成；无需独立评审时所有规定门禁通过，需要评审时评审通过|候选可进入当前层级的整合或采用|
|已完成但评审未通过|执行者声明完成并交付候选；正式独立评审判定不通过|核心任务不变时，记为该模型层级一次有效失败|
|停止并报告|执行者尚未声明完成，因设计冲突、条件不足、门禁不可能通过、环境、权限、范围或安全问题而停止|负责该切片的调度者处理；影响父任务时向上报告|

声明完成前的门禁失败由执行者继续修复或停止并报告，不记为模型失败。缺少规定提交、验证或交付物，不能声明完成。停止并报告后，只有负责该范围的调度者能指出任务说明、外部条件或调度安排发生了有意义的变化并说明它为何提高成功机会时，才重新派遣；若变化会影响继承的任务条件，先向父级报告。否则停止重复派遣并报告真实阻塞。

同一核心任务、同一模型层级累计三次有效失败后才升级。失败连续性不由补充版本编号决定；它由仍有效的行为、授权、起始基线、核心约束和验收条件是否等价决定。详细记录、换人和作废规则见 [调度记录、补充说明与恢复](references/dispatch-records.md)。

升级时，新执行者只收到原始起始基线、当前有效任务说明、权威来源和验收条件，不读取旧实现、失败报告、修复建议、checkpoint 或执行者身份。执行级升级到思考级时采用这份完整上下文隔离。思考级三次有效失败后，负责该切片的调度者先核对是否仍属同一核心任务，再按任务单/补充明确的对象、范围和条件派新的顾问分析 agent；顾问只分析当前任务说明和思考级评审结论，不作决定或实施，也不读取失败实现。若顾问指出任务说明或切分有问题，向父级报告，由根级 Main 修订；只有任务单或补充按上述规则明确授予该范围修订权的父级，才能在命名对象、允许结果、不变量和条件内修订后重新从执行级开始；若涉及产品、授权或风险选择，交给根级 Main；只有任务单或补充按上述规则明确授予该命题的具体决定权时，指定上级才能在命名对象、允许结果和不变量内处理；若无法判断最低可用层级，申请根级 Main 处理用户批准的匿名比较；若规则已唯一决定下一步，负责该范围的调度者安排对应角色执行。

## 决定是否独立评审

委派和评审分别决定。不要因为使用了 subagent 自动增加评审，也不要固定用多个角度重复评审。

|证据情况|处理方式|
|-|-|
|机器门禁已经证明全部重要条件|执行者报告足够，不增加独立语义评审|
|只需核对范围、状态或记录是否完整|由执行级事实核对者检查|
|仍需解释候选行为是否符合契约|由独立思考级评审者判断|
|多个写入切片已整合为一个最终候选|即使门禁通过，也进行思考级最终评审|

“多个写入切片”是两个或更多分别产生可合并状态变化的执行切片；只读调查加一个写入切片不因此算多写入切片。单切片风险高且机器证据不能证明关键语义时，也使用思考级独立评审。当前层级调度者可按上下文长度、可分问题和风险切分多个独立评审或接缝检查；评审者不能扩大范围或安排替代者，无法继续时向直接父级报告。

评审报告的最小字段和修复后的复查规则见 [调度记录、补充说明与恢复](references/dispatch-records.md)。负责该范围的调度者阅读全部评审结论，并逐项记录采用、驳回或继续取证的理由；需要事实或新的语义判断时，分别重新派事实核对或独立评审。

## 整合、完成和清理

整合 agent 只读取最终固定基线、已采用切片提交或产物、共享约束、已知接缝和端到端验收条件；不读取切片对话、旧 checkpoint 或过程记录，也不能修改继承的共享约束。发现冲突时向负责该范围的调度者报告。整合 agent 运行端到端门禁并提交该层级的整合结果。

根级 Main 依据各层级自包含结果、门禁和评审报告判断全局方向与覆盖，无需重读全部原始改动；嵌套调度者只判断自己子树。证据冲突或缺失时，负责该范围的调度者派相应角色补充事实或判断。任务完成前必须同时满足：

- 所有切片已交付或明确取消；
- 需要整合时已经完成整合；
- 所有规定门禁通过；
- 所有必要评审通过；
- 负责该范围的调度者已阅读并判断全部评审结论；
- 没有未解决的产品、授权或风险事项；
- 临时资源已清理，或保留原因已经记录；
- 根级 Main 明确采用最终候选；嵌套调度者向父级交付已采用的子树结果。

合并后由执行级 subagent 制作删除或保留清单，并检查脏文件和未合并的独有内容。负责该范围的调度者处理歧义和授权；不可逆删除由根级 Main 执行，或由任务单/补充按上述规则明确写出授权来源、命名资源、允许动作、必须保持的不变量和执行条件的指定角色执行。没有上述明确授权的脏文件或独有内容保留并报告。批量破坏性任务先由只读执行级 subagent 固定删除与保留清单，再由根级 Main，或由任务单/补充按上述规则明确写出相同授权字段的指定角色，在命名资源、允许动作、不变量和条件内核对歧义后集中修改状态。

只有根级 Main 已获得用户批准，或父任务在任务单/补充中按上述规则明确写出授权来源、命名对象、允许结果或动作、必须保持的不变量和执行条件时，才读取 [匿名模型比较](references/anonymous-comparison.md)。经验记录的写入权限由已声明的经验文件约定；模板见 [经验记录模板](assets/yuna-template.md)。
