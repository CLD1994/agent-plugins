# D2：页面的最小职责

> 状态：`已确认`
>
> 产出：[结论汇总](conclusions.md)
>
> 父主题：[递归讨论草稿方法论与 Skill 设计](../2026-07-18-recursive-discussion-notebook-skill.tmp.md)

## 当前结论

采用“轻量枢纽页 + 单问题讨论页”。

枢纽页只保存：

- 讨论范围；
- 当前状态；
- 子问题索引；
- 关系链接；
- 当前下一步。

枢纽页不承载多个分支的详细论证。

一个讨论页只处理一个可以被独立确认、推翻或重新打开的问题。该问题的当前结论、推理演变和必要例子可以共存，不需要机械拆成三类文件。

## 例子何时独立

例子默认留在对应讨论页。只有在以下情况才独立成页：

- 被多个问题反复引用；
- 例子自身已经明显膨胀；
- 例子拥有独立状态或后续维护需求。

任一讨论页继续产生独立分支时，必须提升为新的次级枢纽页，递归使用同一结构。枢纽不只存在于草稿根；每一层都可以继续建立自己的索引。当前 D10 已经拥有 D10.1 至 D10.20 等独立子问题，因此属于应转换为次级枢纽的真实例子。

## 物理布局

新 skill 创建或正式接管的一个草稿网络必须完整位于同一个自包含目录中：

```text
topic/
├── index.md
├── conclusions.md
└── pages/
    ├── 01-page.md
    └── 02-page.md
```

该目录既是草稿网络边界，也是维护 Agent 唯一的可写根。`index.md` 仍是轻量枢纽页，`pages/` 中的页面仍遵守单问题职责；`conclusions.md` 是唯一、固定、扁平的结论汇总产出页，直接列出当前有效结论及来源链接，不建立分卷或子产出页。

skill 可以在草稿根目录内创建 `.discussion-notebook/` 隐藏管理目录，用于最小登记文件、跨平台操作锁、`operations/` 恢复材料和待移交系统回收站的删除包。结构操作状态必须随草稿本保存，使 Codex 与 Claude Code 都能依据同一事实恢复；平台数据目录只保存运行环境、会话绑定和诊断日志。隐藏管理目录不属于讨论页，不得被索引、Obsidian 内容导航或讨论关系检查当成正文页面，也不得暴露给 Agent 的普通文件工具。

现有“同级索引文件 + 子目录”的历史草稿不自动迁移。只有在用户明确执行 setup 或迁移操作时才转换。

[D12.9](12-9-recursive-hub-layout.md) 已确认次级枢纽采用“完整页面文件主干名目录中的 `index.md` 加直接子项”。例如 `10-maintenance-agent-launch.md` 升格为 `10-maintenance-agent-launch/index.md`，不缩写成 `d10/`，也不在每层重复 `pages/`。
