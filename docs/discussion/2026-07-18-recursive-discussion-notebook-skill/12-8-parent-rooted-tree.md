# D12.8：父主题关系是否必须形成一棵根树

## 要解决的问题

D12.1 已确认除根 `index.md` 外，每个受管理页面恰好有一个 `父主题`。D11 目前又把“无法从根索引沿父子导航到达的页面”列为“疑似孤页”提醒。

这两条规则是否应进一步收口成一个更明确的结构事实：所有页面的父主题链都必须最终到达唯一根 `index.md`？

## 第一性原理

一个有限的页面集合中，如果：

1. `index.md` 是唯一没有父主题的页面；
2. 其他每页恰好有一个存在的父页面；
3. 父主题链不允许形成环；

那么从任意页面不断跟随 `父主题`，必然最终到达 `index.md`。除此之外没有第三种“只是疑似孤立”的结果：到不了根，只可能是父目标缺失、出现第二个无父页面，或者形成父主题环。

因此这里不是在给文本增加语义约束，而是在决定根索引能否作为可靠的完整入口。

## 三种路线

### A：父主题图必须是以 `index.md` 为唯一根的一棵树

检查器把以下事实作为同一个结构不变量：

- 根 `index.md` 不得声明 `父主题`；
- 包括 `conclusions.md` 在内，其他每个受管理页面都恰好有一个父主题；
- 父目标必须是同一草稿网络中的受管理页面；
- 任何页面沿父主题链最终都必须到达 `index.md`；
- 自指、父主题环、第二个无父页面或无法到达根，都属于客观错误；
- 父页面正文仍必须链接回直接子页面，保证人类可以从根逐层向下阅读。

这样一来，D11 的“疑似孤页”提醒应删除，因为它已经被更精确的客观错误覆盖。检查器只需报告无法到根的路径及其具体原因，不再同时发一个含糊提醒。

这是当前推荐路线。

### B：只检查每个页面自己的父主题，不要求整棵树连到根

局部上，每页的父目标都可以存在；整体上，却可能形成一组与根索引隔离的页面。此时 `index.md` 不再是整个草稿网络的可靠入口，用户和 Agent 必须额外扫描目录才能知道是否漏读。

保留“疑似孤页”提醒只能发现问题，不能说明这种结构究竟是否合法，也会让健康检查出现“规则允许、但长期提醒”的中间状态。

### C：允许多个根索引或多个独立页面簇

这相当于把一个草稿目录变成多个草稿网络，却仍共享一个 `conclusions.md`、一个写入边界和一组结构操作。工具需要再发明网络身份、根选择和跨簇产出规则。

如果确实存在两个互不相关的讨论，直接建立两个自包含草稿目录更清楚，第一版没有必要支持森林结构。

## 路线 A 的通俗例子

合法的逻辑结构：

```text
index.md
├── conclusions.md
└── D12
    ├── D12.7
    └── D12.8
```

每个箭头都由子页面的 `父主题` 声明，父页面正文再提供向下链接。无论从哪一页开始，向上都能回到 `index.md`；从根向下也能逐层找到全部页面。次级枢纽怎样映射成文件和目录，由 D12.9 单独确认。

错误结构：

```text
index.md

pages/a.md → pages/b.md → pages/a.md
```

`a.md` 和 `b.md` 的父目标都存在，但它们形成了与根隔离的环。把它叫“疑似孤页”太弱；文件事实已经能够证明根索引不是完整入口。

## 对抗性审查

- **一个页面能否同时属于两个父主题？** 不能。那会把导航从树变成多父图，也与 D12.1 的唯一父主题冲突；其他联系使用依赖、质疑、取代或普通链接表达。
- **物理路径必须跟父子层级一致吗？** D12.8 只确认逻辑根树，不打包决定物理目录。用户已经进一步要求索引拆分递归应用到每层；具体表示转入 D12.9。
- **检查器能否判断父主题选得是否合理？** 不能。它只能证明父链完整；父页面在语义上是否合适仍由 Agent 和用户判断。
- **`conclusions.md` 为什么也要父主题？** 它是草稿网络内唯一产出页，不是第二个根；把它直接挂在 `index.md` 下，人类可以从总入口找到它。
- **删除孤页提醒会不会漏问题？** 不会。如果路线 A 的全部条件成立，孤页在数学上不可能存在；若不成立，检查器会报告更具体的缺父、环或无法到根错误。

## 当前建议

采用路线 A：父主题关系必须形成以 `index.md` 为唯一根的一棵树；任何页面的父链无法到达根都属于客观结构错误。删除重复且含糊的“疑似孤页”提醒。

## 已确认结论

用户确认路线 A：一个草稿目录只讨论一个话题，所有受管理页面必须形成以根 `index.md` 为唯一根的一棵父主题树。父链无法到达根属于客观结构错误，“疑似孤页”不再作为独立提醒。

用户同时确认索引拆分必须递归应用：任何产生独立子问题的页面都应提升为次级枢纽，当前 D10 就属于需要转换的真实例子。下一项转入 [D12.9 次级枢纽怎样映射为目录](12-9-recursive-hub-layout.md)。
