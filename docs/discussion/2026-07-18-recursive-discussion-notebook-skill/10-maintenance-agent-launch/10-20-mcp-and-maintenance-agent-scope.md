## 要解决的问题

MCP（模型上下文协议，保留缩写以对应平台插件能力）最初用于给自动启动的维护 Agent 提供一组受限文件工具，避免它获得通用 shell 和草稿内部目录权限。

D10.19 已经移除自动启动、后台维护、专用会话和任务接管。第一版的实际执行者变成用户当前使用的主 Agent；它本来就运行在用户授权的工作区中，并通过 CLI 执行安全结构操作。

因此需要重新判断：第一版是否还应交付 MCP 服务和无界面维护 Agent 启动器。

## 第一性原理

CLI 和 MCP 不是同一层需求：

- **CLI 的价值：** 把改名、移动、回收、恢复、内容摘要检查和链接校验变成确定性操作，防止 Agent 手工执行多文件修改。
- **MCP 的价值：** 给一个权限受限的独立 Agent 暴露这些操作，同时不让它接触通用文件工具。
- **独立维护 Agent 的价值：** 把大量语义阅读成本放到另一个上下文，或者执行无人值守维护。

第一版仍然需要第一项。取消自动维护以后，后两项暂时没有当前执行者。

## 三种路线

### A：第一版继续交付 CLI、MCP 和独立维护 Agent

它完整保留早期架构，但需要维护两个平台的无界面启动器、MCP 生命周期、权限配置、会话恢复和故障处理。没有自动任务或真实大规模恢复场景时，这些代码只能通过人为构造的路径使用。

这条路线为未来需求提前交付过多能力。

### B：第一版只交付 CLI 和共同 Python 核心

Python 核心保存全部路径校验、结构操作、操作日志、回收站和检查规则。CLI 是第一版唯一适配层，主 Agent 按 skill 调用它。

显式恢复有两种简单方式：

- 当前主 Agent 在当前会话中运行恢复或健康检查命令；
- 用户明确新建一个普通会话，显式选择草稿网络并调用同一 skill 与 CLI。

第二种方式已经把阅读成本放进独立上下文，但不需要插件自己启动或管理这个会话。因为会话由用户创建，它与普通主 Agent 具有相同的用户授权边界。

共同核心保持清楚的 Python API，不需要预先建立抽象接口或空适配层。未来增加 MCP 时，薄适配器直接调用这些函数，不能重新实现业务规则。

这是当前推荐路线。

### C：第一版连 CLI 也取消，让 Agent 直接编辑文件

这会失去安全改名、链接修复、崩溃恢复、可恢复回收和内部目录隔离。Agent 必须重新手工拼接多文件操作，违背 D10.5 至 D10.8 已确认的正确性边界。

这条路线简化过度，不应采用。

## 对 D10.9 与 D10.10 的影响

若采用路线 B：

- D10.9 的“维护 Agent 只能通过 MCP 访问文件”仍是未来自动或权限受限维护 Agent 的安全前提，但第一版没有这种 Agent，因此不实现 MCP 服务；
- D10.10 的“CLI 与 MCP 共享同一核心”保留为未来扩展方向；第一版只实现共同 Python 核心和 CLI，不创建没有调用者的 MCP 入口；
- 不实现 `codex exec`、`claude -p` 启动器、专用维护会话、会话压缩、后台任务、完成通知或占用权；
- D10.4 至 D10.8 的目录边界、结构操作、操作日志和回收站继续由共同核心与 CLI 落实。

## 安全性对抗审查

- **主 Agent 有 shell，能否绕过 CLI？** 能。CLI 不是主 Agent 的权限沙箱，而是确定性安全操作入口。skill 必须要求结构操作使用 CLI；用户当前主 Agent 本来就拥有工作区权限，第一版不假装把它变成不可信后台进程。
- **提示注入要求主 Agent 直接删除文件：** CLI 能保护通过它发起的操作，但不能阻止已获 shell 权限的 Agent 绕过。真正需要强制隔离时，必须使用 D10.9 的 MCP-only 边界，并同时撤销通用文件工具；这属于未来独立执行者。
- **显式恢复内容太大：** 用户可以新建普通会话，把阅读成本放到新上下文。只有当手动建立会话频繁、容易出错或需要无人值守时，插件才需要启动器和会话管理。
- **未来增加 MCP 会不会大改核心？** 如果业务规则已经收口在普通 Python 函数中，MCP 只增加参数转换和结构化返回。无需现在创建接口类、服务生命周期或占位代码。

## 当前建议

第一版只交付共同 Python 核心、CLI、skill 和压缩后重新绑定入口。不交付 MCP 服务、无界面维护 Agent 启动器或专用维护会话。

未来出现权限受限的独立执行者、无人值守恢复或频繁的大规模整理后，再实现 MCP 薄适配层和相应启动生命周期。

## 已确认结论

用户确认：第一版只实现共同 Python 核心和 CLI，不交付 MCP 服务与独立维护 Agent；D10.9 的 MCP-only 安全边界作为未来引入权限受限执行者时的前置条件保留。
