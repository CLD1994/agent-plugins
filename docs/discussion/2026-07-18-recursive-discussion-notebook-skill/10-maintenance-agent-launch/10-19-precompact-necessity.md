## 要解决的问题

压缩前钩子（`PreCompact`，保留字面量以对应两个平台的生命周期事件）只有在某项工作必须赶在上下文压缩前完成时才有存在理由。

经过 D10.14 至 D10.18 的修正，第一版已经不再计划：

- 在压缩前复制平台转录；
- 保存逐轮已整理位置；
- 自动计算并派发语义维护缺口；
- 让压缩后的主 Agent 重读原始历史；
- 为每轮保存 `updated` 或 `no_change`。

因此必须重新证明 `PreCompact` 还剩下什么不可替代的职责，而不能因为早期设计使用过它就继续保留。

## 第一性原理检查

### 即时语义维护

用户确认、否定、提出决定性反例或打开新分支时，Agent 在当前上下文仍然新鲜的情况下立即修改草稿。这件事发生在正常讨论中，不依赖压缩事件。

### 结构操作恢复

页面拆分、移动、重命名和回收涉及多文件写入，D10.6 已要求暂存、内容摘要和耐久操作日志。进程即使在压缩前后崩溃，恢复依据都在磁盘上，不需要 `PreCompact` 再复制一次。

### skill 连续性

D10.16 使用压缩后和恢复时的重新绑定信封，让 Agent 重新读取当前 skill。需要的是压缩后的会话启动入口，不是压缩前入口。

### 异常语义遗漏

D10.18 已接受第一版不自动发现“收到用户结论后、写入草稿前崩溃”的极短窗口。既然不维护完成位置，`PreCompact` 也无法确定应该补读哪段内容；强行启动维护 Agent 只能重新引入大范围猜测和读取。

逐项检查后，目前没有工作必须在压缩前完成。

## 三种路线

### A：继续保留完整压缩前协调器

它可以启动独立维护 Agent、等待、超时和保存退路任务。但没有可靠缺口边界后，协调器不知道维护 Agent 应处理什么。若默认读取最近若干轮，范围是猜的；若读取全部历史，又违背 D10.15。

这条路线保留了最多复杂度，却失去了明确输入，不应采用。

### B：保留一个只做环境检查的空钩子

钩子检查 uv、Python 和插件环境是否健康，失败时警告并放行压缩。它看似便于以后扩展，但第一版没有后续维护工作要运行，环境检查结果也不会改变压缩行为。

为了发现“一个当前没有用途的运行时不能启动”，给每次压缩增加脚本、信任配置和故障面，没有实际收益。

### C：第一版不注册压缩前钩子

正常流程变为：

1. Agent 按 skill 在讨论过程中即时维护草稿；
2. 结构操作通过耐久日志保护；
3. 宿主自行完成上下文压缩，不被插件阻塞；
4. 压缩后的会话启动入口重新绑定 skill 和当前草稿网络；
5. 已知发生异常时，用户或 Agent 显式运行健康检查或恢复流程。

这是当前推荐路线。

## 对早期已确认内容的影响

如果采用路线 C，需要明确修正而不是悄悄保留冲突：

- D6.2 的“压缩前钩子唤起专用维护子 Agent”退出第一版；
- D9 的“环境损坏时由极薄入口保存压缩前输入”退出第一版，因为已经没有必须保存的压缩前输入；
- D10.1、D10.2、D10.3、D10.11 和 D10.12 依赖自动维护会话生命周期，不进入第一版；
- D10.4 至 D10.10 关于目录权限、结构工具、操作日志、回收站和 CLI/MCP 共同核心仍然有价值，可用于主 Agent 的正常维护和显式恢复；
- 独立维护 Agent 仍可作为以后显式健康检查或大规模整理的执行方式，但不再由压缩生命周期自动启动。

D9 的 Python、uv、独立虚拟环境和 setup 指导仍然成立。被移除的只是为压缩前自动维护准备的应急入口。

## 对抗性审查

- **Agent 快到上下文极限才想起维护：** 这是即时维护纪律已经失效；没有已整理位置时，压缩前钩子也无法可靠知道遗漏内容。保留钩子不能修复一个没有边界的输入。
- **压缩发生在多文件操作中间：** 操作日志保护磁盘一致性；上下文压缩不应决定文件事务能否恢复。
- **skill 重新绑定钩子失效：** 用户仍可显式调用 skill。增加另一个压缩前钩子不会让失效的安装自动恢复。
- **以后确实需要无人值守补漏：** 先增加 D10.18 路线 B 的累计已整理位置，再重新引入具有明确输入的生命周期协调器；不能只恢复一个空钩子。
- **平台未来提供更强的 Agent 钩子：** 能力变强不等于需求出现。只有明确的压缩前职责出现时才使用。

## 当前建议

第一版完全不注册 `PreCompact`。压缩生命周期只使用压缩后的重新绑定入口；正常维护发生在讨论过程中，异常恢复由显式流程触发。

## 已确认结论

用户确认：第一版移除 `PreCompact` 及其应急保存、自动启动、等待和后台任务设计；保留压缩后的 skill 重新绑定，并把独立维护 Agent 降为显式恢复或整体整理能力。
