## 用户对 `产出` 的纠正

`产出` 不是从草稿指向草稿根外的正式设计或其他外部制品。

讨论完成后，草稿网络需要一个结论汇总产出页。已经确认且当前未被取代的来源页使用 `产出` 指向该页；产出页概括每项有效结论并链接回详细来源，让其他流程先读摘要，再按需深入论证。

产出页仍位于草稿根内，仍是临时草稿。它只是后续设计流程的输入，不会因为被称为“产出”就自动获得正式批准地位。

## 已确认链接范围

所有结构标签都只能指向同一草稿网络中的受管理页面：

- `父主题`
- `依赖`
- `取代 / 被取代`
- `质疑 / 被质疑`
- `产出`

只有正文普通 Markdown 链接可以引用草稿根外的本地文件或网页资料。普通链接不建立正式关系，也不扩大结构工具的写权限。

因此 D11 的安全规则可以直接收口为：任一结构标签解析后的真实路径必须留在草稿根内；符号链接也不能把结构标签目标绕到根外。

## 产出关系的两端

来源页保存正式标签：

```markdown
> 产出：[结论汇总](../conclusions.md)
```

产出页正文保存简短结论和来源导航：

```markdown
## 已确认结论

- 请求身份必须由请求内容指纹共同约束。详见 [请求幂等](pages/request-idempotency.md)。
```

与父子导航相同，两个方向的链接职责不同：

- 来源页的 `产出` 建立机器可识别关系；
- 产出页正文的摘要和链接服务人类及后续流程的渐进阅读；
- 产出页正文单独出现普通链接，不会自动把目标认定为已确认产出来源；
- 不新增 `来源于` 标签，反向来源集合由工具从 `产出` 推导。

## 检查器能证明什么

- `产出` 目标必须是草稿根级唯一固定的 `conclusions.md`；
- 产出页正文链接回每个声明指向它的来源页；
- 同一来源和产出页关系没有重复；
- 除 `conclusions.md` 自身外，每个 `已确认` 页面必须声明且只声明一次 `产出`；其他状态不能声明 `产出`；
- `已取代` 与 `被取代` 必须一致；
- 结构操作没有把产出关系或返回链接改坏。

## 检查器不能证明什么

检查器能够识别 `状态` 的生命周期前缀，但不能判断 Agent 是否把页面归入了正确状态，也不能判断产出页的自然语言摘要是否准确。

因此以下工作仍由 Agent 完成、用户评审：

- 用户确认结论后，把来源页状态改为 `已确认`，添加 `产出` 并更新汇总；
- 结论被取代后，移除旧来源的 `产出` 和旧汇总条目；
- 判断页面在语义上是否真的已经确认、关闭或取代；
- 确认摘要没有把尚未批准的提案写成结论。

检查器可以机械发现“状态已经写成 `已确认`，却漏了产出”的矛盾，但不伪装成能够替 Agent 决定状态。

## 已确认结论受到未解决质疑时

`已确认` 与 `被质疑` 可以同时存在。`已确认` 表示结论当前仍被接受，`被质疑` 表示有一个尚未解决、会威胁它的挑战；提出挑战本身不会自动撤销已经作出的决定。

此时来源页仍保留 `产出`，但产出页对应条目必须显式提示该结论仍被质疑。若用户判断质疑已经使原结论不再具有当前效力，Agent 把来源页改回 `当前提案` 并移除 `产出`，直到重新确认或关闭。检查器验证标签和产出集合，是否撤销当前效力仍是用户的语义决定。

## 为什么这仍然支持正式设计流程

后续流程只需要从产出页开始：

1. 读取当前有效结论的短摘要；
2. 按需打开来源页查看推理、反例和确认过程；
3. 根据目标文档的读者和用途重新组织内容；
4. 在用户明确授权后生成或修改正式设计。

正式设计文件与草稿之间可以保留普通 Markdown 链接，但不使用 `产出` 建立根外正式关系。

正式设计已经吸收某项结论，不会让该结论失效。为了避免汇总页复制越来越多正式文档内容，Agent 可以把已迁移的长条目压缩成一行，只保留结论本身、草稿来源和正式文档链接；它仍是当前有效结论的紧凑条目，不是已经失效的归档。

## 已确认结论

用户确认：`产出` 只用于草稿网络内部，由已确认且当前未被取代的来源页指向结论汇总产出页；产出页正文汇总结论并链接来源。所有结构标签都必须留在草稿根内，只有正文普通链接可以引用外部目标。

[D12.6](12-6-output-page-cardinality.md) 已确认每个草稿网络只有一个固定、扁平且不分卷的 `conclusions.md` 产出页。下一项转入 [D12.7 依赖关系能否形成环](12-7-dependency-cycles.md)。
