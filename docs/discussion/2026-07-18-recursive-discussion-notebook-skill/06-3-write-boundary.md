# D6.3：自动修改边界

> 状态：`已确认`
>
> 产出：[结论汇总](conclusions.md)
>
> 父主题：[D6 维护与检查](06-maintenance.md)

## 当前结论

采用不对称权限：检查工具保持只读；维护 Agent 可以依据明确事实有限写入临时草稿。

## 检查工具

检查工具只报告结构错误和审查提醒，不提供会猜测意图的通用自动修复。

例如断链可能意味着目标被重命名、文件被误删、链接已经过时或讨论已经关闭。工具无法仅从“目标不存在”判断正确修复方向。

## 维护 Agent 可以执行

- 记录本轮已经明确形成的当前提案；
- 同步用户明确确认、否定或重新打开的状态；
- 更新父级摘要和下一步；
- 创建已经明确需要的讨论页；
- 在自己执行一次已知的重命名、移动或拆分时，同步修复目标唯一的链接变化。

## 遇到歧义时停止推断

如果一句确认可能指向多个问题、断链可能有多个目标，或者拆分边界需要新的语义判断，维护 Agent 只记录审查提醒，不自行选择。

维护 Agent 不得从关键词推断确认，不得自行解决质疑、删除无法理解的历史或迁移正式设计。压缩前子 Agent 不进行大规模重组。

核心边界是：机器检查不改文件；推理型维护者只写入已有明确依据的变化；有歧义就留下待审查线索。
