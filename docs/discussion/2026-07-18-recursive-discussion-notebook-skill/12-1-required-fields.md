# D12.1：最少必须有哪些结构字段

> 状态：`已确认`
>
> 产出：[结论汇总](conclusions.md)
>
> 父主题：[D12 最小机器可识别结构使用什么 Markdown 语法](12-minimal-structure-syntax.md)
>
> 依赖：[D2 页面的最小职责](02-page-model.md)、[D5 链接格式与反向查找](05-links-and-backlinks.md)、[D11 第一版检查器范围](11-checker-scope.md)

## 要解决的问题

D12 已确认机器只解析页面一级标题后的连续引用块。本页决定每个页面最少必须提供哪些结构字段。

目标不是收集“以后可能有用”的元数据，而是只保留当前检查器、导航和安全结构操作真正需要的事实。

## 第一性原理

第一版工具需要回答：

1. 页面当前处于什么人类可见状态；
2. 页面在递归讨论树中直接归属于哪个父页；
3. 改名、移动或检查时需要修复哪些明确链接。

标题已经由一级标题提供，文件路径已经唯一定位页面。没有任何当前操作需要创建时间、更新时间、标签、作者、页面类型或随机标识。

## 三种路线

### A：只要求 `状态`

父主题完全依靠普通正文链接和索引推断。页面可以自由书写，但工具无法区分“这个链接是父页”还是“只是正文引用”，父子导航检查和安全移动都要猜。

不够。

### B：只要求 `状态` 与 `父主题`

普通页面顶部最小结构为：

```markdown
# 示例问题

> 状态：`当前提案`
>
> 父主题：[链接格式与反向查找](05-links-and-backlinks.md)
```

- `状态` 必须存在，并以 `待讨论`、`当前提案`、`已确认`、`已取代`、`已关闭` 之一开头；前缀后可以使用全角冒号补充自由说明。
- `父主题` 必须恰好包含一个 Markdown 链接，表示唯一直接父页。
- 根 `index.md` 没有父页，因此只要求 `状态`。
- 页面顶部仍可加入其他人类提示；未知行不会自动变成机器字段。

这是当前推荐路线。

### C：同时要求 ID、类型、日期、标签和版本

这些字段看似完整，但第一版没有消费者：

- 页面 ID 会与相对路径形成两套身份；
- 页面可能从讨论页自然成长为子枢纽，固定类型会增加迁移；
- 日期和更新时间容易与文件历史重复或漂移；
- 标签不是已确认的正式关系；
- 版本字段没有对应的并发或迁移协议。

这条路线属于预先建模，不应采用。

## 为什么采用有限前缀而不是完全自由文本

完全自由文本无法让检查器区分“正在讨论”“当前提案”“已经确认”和“只保留历史”。这样即使链接全部正确，旧提案仍可能被误当成当前事实，检查器也无法证明 `conclusions.md` 是否漏掉了一个已经明确标为确认的页面。

第一版只固定五个生命周期前缀，不固定前缀后的说明：

```markdown
> 状态：`已确认`
```

或者：

```markdown
> 状态：`已关闭：历史条件方案，第一版不采用`
```

检查器先解析 `状态：` 标签，再读取状态值内部第一个全角冒号之前的前缀；值内说明部分仍由人类自由书写。这样既保留真实草稿所需的细节，又给产出完整性和旧提案识别提供最小机械抓手。

程序仍不能判断 Agent 是否选对了前缀；它只能证明前缀属于允许集合，以及该前缀与 `被取代`、`产出` 等结构关系是否一致。

## 为什么不需要稳定页面 ID

草稿网络是本地自包含目录，正式关系使用相对 Markdown 链接。页面改名和移动必须经过安全 CLI，由它修复引用并运行检查。

稳定 ID 只有在大量外部系统独立引用页面、路径频繁变化且无法统一修复时才有明显价值。第一版没有这个需求；相对路径是唯一页面身份，避免维护额外注册表。

## 父子关系与普通链接

`父主题` 是子页面对父关系的唯一正式声明。父页面为了人类导航仍需在任意正文位置链接到子页面，但不要求固定的“子主题”章节标题。

检查器据此执行：

- 子页面的 `父主题` 目标必须存在；
- 父页面必须在普通 Markdown 内容中链接回子页面；
- 父页面存在普通链接并不自动说明目标是子页面；正式方向只由子页面的 `父主题` 决定。

这样既能双向阅读，又不需要在父页重复维护机器关系清单。

## 根索引和枢纽页怎样选择状态

状态描述当前页面自身，不汇总后代页面。只承担链接导航、不表达问题或方案的根索引或枢纽页使用 `已关闭：纯导航页，不表达独立结论`，无论子页仍在讨论还是已经确认；页面自身记录了尚未讨论的问题时使用 `待讨论`，承载当前方案时使用 `当前提案`。它不能因为子页已经确认就机械变成 `已确认`。

如果根索引或枢纽页自身提出了一项没有被子页重复表达的独立结论，它可以使用 `已确认`，并和普通来源页一样声明 `产出`。因此路径角色不豁免产出规则，只有固定产出页 `conclusions.md` 自身例外。

## 对抗性审查

- **有限前缀会不会约束自然语言？** 只约束生命周期类别。历史条件、未来边界和关闭原因继续写在冒号后的自由说明中；正文不受影响。
- **路径身份在改名时会变化：** 正是安全改名 CLI 的职责。新增 ID 不会消除链接修复，只会增加另一项同步状态。
- **一个页面能否有多个父主题？** 第一版不能。递归导航需要一个直接父页；其他结构联系使用依赖、取代、质疑或产出关系。
- **根索引是否需要特殊类型字段？** 不需要。路径恰好为草稿根的 `index.md` 已经能确定它是根入口。
- **页面成为枢纽怎么办？** 父页面开始链接子页即可，不需要修改类型字段。

## 当前建议

第一版只有两个基础结构字段：所有页面都要求一个带已知生命周期前缀的 `状态`；除根 `index.md` 外，所有页面还要求恰好一个 `父主题` Markdown 链接。不增加 ID、类型、日期、标签、作者、更新时间或版本。

## 已确认结论

正式设计评审修正路线 B：第一版基础字段仍只有 `状态` 和单一 `父主题`，但 `状态` 改为五个机器可识别前缀加可选自由说明。根 `index.md` 不要求父主题；第一版不增加 ID、类型、日期、标签、作者、更新时间或版本。
