## 要解决的问题

第一版需要只读检查器保护草稿网络不被结构操作损坏，但不能重新走向“给 skill 和自然语言草稿写固定文本测试”。

本页只决定检查边界，不提前固定状态行、关系声明和导航区的具体 Markdown 语法。机器可识别的最小语法需要下一项单独确认。

## 第一性原理

检查器只应回答普通程序能够根据文件确定的问题：文件是否存在、路径是否安全、链接是否断裂、明确声明的结构是否自相矛盾。

需要理解讨论含义的问题必须留给 Agent 和用户：摘要是否准确、反例是否成立、页面是否真的应该拆分、旧方案是否已被取代。

如果一个规则只能通过猜测自然语言才能检查，它就不属于第一版检查器。

## 三种路线

### A：不提供检查器

它避免机器约束文本，但安全改名、移动、回收和链接修复失去完成判据。多文件操作可能在留下断链或孤页后仍被报告为成功。

这会削弱 D10.5 至 D10.8，不能采用。

### B：建立广泛的语义检查器

它尝试判断标题是否规范、摘要是否完整、每页是否只有一个问题、质疑是否解决、结论是否足够详细。

这些判断依赖语境，程序只能靠关键词、固定标题或模板猜测。结果会迫使作者为检查器写文字，也与 D7 的人工阅读和真实场景试用冲突。

这条路线不成立。

### C：只检查客观结构事实

检查器保持只读，只输出两种结果：

- **客观错误：** 文件事实已经证明结构损坏，安全结构操作不能把它当作成功；
- **审查提醒：** 文件事实只说明值得 Agent 看一眼，不能自动修改或阻止普通讨论继续。

这是当前推荐路线。

## 第一版客观错误

在相应最小语法确认后，第一版检查以下错误：

- 草稿根缺少 `index.md`、`conclusions.md` 或 `pages/`；
- 在受管理模式下缺少 `.discussion-notebook/notebook.json`，或者 `format_version` 缺失、类型错误或取值非法；
- 登记的 `format_version` 高于当前工具认识的版本，或者不是当前可写版本；前者要求先升级工具，已知旧版本要求显式迁移，二者都不能继续结构写操作；
- 本地 Markdown 链接目标不存在；
- 任一结构标签指向草稿根外，或通过符号链接绕到根外；
- 普通页面直接链接或写入 `.discussion-notebook/` 内部管理目录；
- 正式关系使用未知关系类型，标签格式损坏，或目标页面不存在；
- `状态` 缺失、重复、格式损坏，或者没有使用五个已知生命周期前缀之一；
- 一个关系标签行没有恰好包含一个目标链接，或同一标签重复指向同一规范化目标；
- 除根 `index.md` 外，页面缺少、重复或写空唯一的 `父主题`，根索引错误声明了父主题，或者任一页面的父主题链无法最终到达根索引；
- 次级枢纽目录缺少 `index.md`，或者页面的物理父目录与其 `父主题` 声明不一致；
- 非根枢纽在一次结构操作完成后没有任何直接子页；操作暂存过程中的中间状态不单独检查；
- 子页面通过 `父主题` 声明父页面后，父页面正文没有链接回该子页面；父页面中的普通链接本身不声明子关系；
- 页面依赖自己，或者任意多个页面的 `依赖` 关系形成闭合环路；
- `取代 / 被取代` 或 `质疑 / 被质疑` 没有成对互相指向，或者取代关系形成自相矛盾的结构环；
- `已取代` 与 `被取代` 不一致；
- 除 `conclusions.md` 自身外，`已确认` 页面缺少或重复 `产出`，其他状态错误声明 `产出`，`产出` 没有指向根级固定 `conclusions.md`，或者该页正文没有链接回来源页；
- 已开始的结构操作日志处于无法解释的状态，不能安全继续、回滚或报告完成。

这里检查的是明确声明之间是否一致，不从正文句子推断关系或状态。

`已确认 + 被质疑` 是允许组合：结论当前仍有效，但存在未解决挑战。检查器分别验证该页的产出完整性和质疑关系双向一致性，不把组合本身报告为错误，也不通过固定措辞判断产出页是否充分说明了挑战。

## 第一版审查提醒

- 除固定 `conclusions.md` 外，页面超过约 600 行或 60 KB，建议 Agent 评审是否拆分；
- 页面现有父主题目标值得人工复核，但仅凭文件事实无法确定更合适的父页。

提醒不能自动改文件，不能把页面判为无效，也不能单独让整个检查命令以“内容错误”失败。结构操作若正要制造对应问题，可以根据操作自身的后置条件拒绝完成。

## 第一版明确不检查

- 标题、段落、摘要、例子或结论的固定措辞；
- 章节顺序和是否使用某个固定标题；
- 页面是否真的只包含一个独立问题；
- 质疑是否成立或已经解决；
- 新方案是否在语义上取代旧方案；
- Agent 是否为页面选择了语义上正确的状态前缀；
- 产出页中的结论摘要是否准确、完整；
- 当前下一步是否合理；
- 拼写、文风或篇幅是否“足够好”；
- 外部网页是否仍可访问；
- skill 的全文、提示词或生成结果是否匹配快照。

## 程序怎样验证

检查器代码使用小型人工构造文件夹验证：断链、路径逃逸、父子不一致和容量提醒等输入应产生对应错误编号或提醒编号。

测试断言结构化编号、涉及路径和严重级别，不断言完整中文诊断句子，也不把真实讨论页全文复制成固定快照。测试覆盖状态前缀、状态与产出的对应关系；真实草稿只用于人工试跑和发现新场景，不成为要求文字永远不变的黄金样本。

## 对抗性审查

- **固定关系语法会不会约束文本？** 会约束极小的结构声明，但不约束正文。没有任何可识别结构时，安全改名和关系检查也无法可靠工作；下一项需要把这部分语法压到最小。
- **Markdown 解析器能否理解所有写法？** 第一版只承诺自己生成和记录的最小结构语法；普通 Markdown 链接按标准解析，无法识别的扩展语法不应被猜测。
- **检查全绿是否代表内容正确？** 不代表。它只说明没有发现机械损坏；语义仍由 Agent 判断、用户确认。
- **警告越来越多怎么办？** 新警告必须对应可观察文件事实和明确人工动作，不能把“也许内容不好”包装成规则。

## 当前建议

第一版采用路线 C：只读检查器只验证客观结构事实，并把容量等不确定情况作为审查提醒。任何需要理解自然语言的判断都不进入程序。父链无法到达唯一根索引已经由 D12.8 确认为客观错误，不再保留含糊的“疑似孤页”提醒。

## 已确认结论

用户确认：第一版检查器只检查上述客观结构错误与审查提醒，不检查固定标题、正文措辞或讨论语义。容量行数提醒由约 300 行放宽到约 600 行。

[D11.1](11-1-capacity-threshold.md) 已确认完整容量提醒为“约 600 行或 60 KB”。D12.10 进一步确认，结构操作完成后遗留的非根空枢纽属于客观结构错误，而不是审查提醒。D13.1 确认只有当前 `format_version` 可以进入完整检查后的正常写操作；旧版本和未知新版本都必须拒绝写入，但给出不同的后续动作。
