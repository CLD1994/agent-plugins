# D12.3：同一标签有多个目标时怎样表达

> 状态：`已确认`
>
> 产出：[结论汇总](conclusions.md)
>
> 父主题：[D12 最小机器可识别结构使用什么 Markdown 语法](12-minimal-structure-syntax.md)
>
> 依赖：[D12.1 最少必须有哪些结构字段](12-1-required-fields.md)、[D12.2 正式关系由哪一侧声明](12-2-canonical-relation-direction.md)

## 要解决的问题

一个页面可能依赖多个前提、取代多个旧方案、受到多个质疑或产出多个文件。第一版需要一种简单、可读、容易局部修改的多目标语法。

`状态` 和 `父主题` 已经确认只能各出现一次。本页只讨论可以拥有零个或多个目标的关系标签。

## 第一性原理

合适的语法应该满足：

- 人类能一眼看出每条关系指向谁；
- 删除一条关系时只改一小行；
- 检查器不需要解析中文逗号、英文逗号或自然语言连接词；
- `取代 / 被取代`、`质疑 / 被质疑` 可以逐条精确配对；
- Git diff 和操作日志能清楚显示新增或删除了哪条边；
- 不引入嵌套列表或另一套配置语法。

## 三种路线

### A：一个标签行放多个链接

```markdown
> 被质疑：[并发反例](challenge-a.md)、[权限反例](challenge-b.md)
```

它很紧凑，但一行承担多条边。删除、排序或解决其中一个质疑时都要重写整行；检查器还要规定允许哪些分隔符，以及链接之间能否出现说明文字。

### B：每个标签行只放一个链接，标签可以重复

```markdown
> 被质疑：[并发反例](challenge-a.md)
>
> 被质疑：[权限反例](challenge-b.md)
```

规则是：

- `状态` 必须恰好出现一次；
- 非根页面的 `父主题` 必须恰好出现一次，根索引不得出现；
- `依赖`、`取代`、`被取代`、`质疑`、`被质疑`、`产出` 可以出现零次或多次；
- 每次出现必须恰好包含一个 Markdown 链接；
- 相同标签指向同一规范化目标两次，属于重复关系错误；
- 同一标签指向不同目标是合法的，文件顺序只服务阅读，不改变关系含义。

这是当前推荐路线。每一行就是关系图中的一条边，也正好是检查器和结构操作处理的最小单位。

### C：标签后使用嵌套 Markdown 列表

```markdown
> 被质疑：
> - [并发反例](challenge-a.md)
> - [权限反例](challenge-b.md)
```

它能表达多个目标，但引入了引用块内嵌套列表、缩进和连续性规则。对第一版而言，这比重复一行多出了一层没有实际收益的语法。

## 成对标签怎样检查

假设当前方案受到两个质疑：

```markdown
# 当前方案

> 状态：`当前提案`
>
> 被质疑：[并发反例](challenge-a.md)
>
> 被质疑：[权限反例](challenge-b.md)
```

两个质疑页面分别保存：

```markdown
> 质疑：[当前方案](current-plan.md)
```

检查器按每个“标签 + 规范化目标路径”建立一条边，然后逐条核对：

- `challenge-a.md` 指向当前方案的 `质疑`，必须对应当前方案指回它的 `被质疑`；
- `challenge-b.md` 同理；
- 多一个或少一个反向标签都属于客观结构错误；
- 解决其中一个质疑时，只删除对应两行，另一条关系不受影响。

`取代 / 被取代` 使用完全相同的配对规则。

## 对抗性审查

- **重复标签看起来会不会冗余？** 标签重复是为了让每一条关系独立。相比把多个目标塞进一行，它让编辑、诊断和崩溃恢复都更局部。
- **是否应该把目标排序？** 第一版不强制。强制排序只会制造无意义改动；检查器按规范化路径比较集合，不依赖文件顺序。
- **一行能否写两个链接，其中一个只是说明？** 不能。关系行只能有一个目标链接；额外解释放在正文，避免检查器猜哪个链接才是关系目标。
- **多个 `父主题` 能否用同样方式表达？** 不能。父主题定义递归导航中的唯一直接父页，D12.1 已确认只能有一个。
- **空标签能否表达“当前没有质疑”？** 不能。没有关系就不写该标签；空行只会增加一种需要解释的状态。

## 当前建议

采用路线 B：可重复的关系标签每行只表达一个链接目标；同标签不同目标合法，同标签同目标重复属于客观错误；顺序不具有协议含义。

## 已确认结论

用户确认路线 B：

- 一个关系标签行只放一个 Markdown 链接目标；
- 通过重复标签表达多个目标；
- 同标签不同目标合法，同标签同一规范化目标重复属于客观错误；
- 标签顺序不具有协议含义；
- `状态` 和 `父主题` 仍分别只能出现一次。
