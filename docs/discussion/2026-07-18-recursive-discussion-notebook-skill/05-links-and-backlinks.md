## 当前结论

采用“标准 Markdown 保存关系；普通反向查找由工具推导；会改变目标页面当前理解的反向事实必须显式写回目标页面”。

- 文件只使用标准 Markdown 链接，不使用 `[[Wiki Link]]`。
- 人类默认通过 Obsidian 阅读，使用反向链接功能查看入站关系。
- Agent 可以用普通文件搜索推导相同的反向关系。
- `依赖 / 被依赖` 不改变目标页面的有效性，只保存 `依赖`，反向按需推导。
- 已确认且当前未被取代的来源页保存 `产出`；草稿内产出页必须在正文汇总该结论并链接回来源，但不重复保存 `来源于` 标签。
- `取代 / 被取代`、`质疑 / 被质疑` 会改变目标页面的当前理解，必须在两端保存相互对应的标签和链接。

## 仍需在两端出现的导航

父页面保留子主题索引，子页面保留父主题入口。它们服务于各自页面的直接阅读路径，不是为了形式上的关系对称。

## 必须写回页面的反向事实

反向查找不能替代页面自身的有效性提示。

如果入站关系会改变当前页面的有效性，例如页面已经被取代，或者正受到尚未解决的质疑，受影响页面顶部必须分别使用 `被取代` 或 `被质疑` 标签链接到来源。

`被依赖`只帮助发现引用者，不必写回目标页面。`来源于` 不作为标签写回，但产出页正文必须保留来源结论的摘要和导航链接，以支持渐进阅读。

因此不需要额外的 `状态依据` 标签，也不需要把来源链接塞进状态说明。核心判断是：普通反向“查找”交给 Obsidian 或文件搜索；影响当前理解的反向事实直接作为明确标签写在页面上。
