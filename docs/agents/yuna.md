# Yuna 调度经验

本文件是有证据支持的调度经验记录，不是任务规格、完整难度分类器、用户授权、权限边界或验收条件。当前任务仍由根级 Main Agent 根据其权威来源和用户决定。新条目使用 [经验记录模板](../../.agents/skills/i-am-yuna/assets/yuna-template.md)。

经验适用于根级 Main Agent 及在父任务明确范围内负责下级的嵌套调度者。嵌套调度者只在自己的子树内应用经验，继承的目标、授权、范围、基线和共享约束保持不变；需要改变这些条件时向父级报告。

## 写入权限

|分区|可以写入的人|限制|
|-|-|-|
|Main 调度经验|根级 Main Agent|只记录有具体证据的调度、任务切分和上下文压缩经验；单次事件只能形成窄结论，推广为规律需要重复或相互独立的证据|
|匿名比较与模型难度记录|身份揭示前已经固定结论的独立评估者|只记录匿名比较或模型难度结论；固定结论后、揭示身份前写入|

两类记录都不能修改任务规格、候选实现或用户授权。

## 模型难度记录

以下既有判定尺度已验证，用于描述完成任务所需的最低稳定干预层级，不按具体模型名称、单次表现或主观印象判定。后续模型难度结论只由具有相应权限的独立评估者写入。

|最低层级|判定依据|
|-|-|
|执行级|执行级模型在三次执行内稳定满足验收条件|
|思考级|执行级模型失败，思考级模型从原始基线重新实施后在三次内满足验收条件|
|顾问级|执行级和思考级模型均失败，需要顾问级模型的分析，或在根级 Main 已获得用户批准（或父任务按窄授权规则明确获准）的匿名比较中按执行角色另行记录的完整路线，才能满足验收条件|
|人类介入|顾问级执行角色累计三次有效失败，或最终结果无法可靠判断；顾问分析不产生候选，不计入执行失败|

目前没有可公开的具体匿名比较条目。

## Main 调度经验

### 权威分散的跨来源审查与规格收敛

#### 任务特征

- 当前行为分散在多份历史规格、候选文档、实现和测试中，其中可能混有未经签署的推论。
- 需要同时判断既有权威是否已给出答案、候选是否发生漂移，以及真正需要人类决定的语义。
- 预期产物包含跨对象矩阵或全量覆盖清单，容易把事实发现、权威裁决和实现观察合并成一次宽委派。

#### 已确认的调度结论

不要直接为整个组合任务评定模型层级。一次委派同时要求全库发现、选择权威、建立完整矩阵并综合决策时，任务边界没有自然终点；提升模型层级不能补全不稳定的权威上下文，通常只会增加读取和推理成本，也不能据此证明模型能力不足。

负责该范围的调度者先建立待判定命题和覆盖清单，再按以下顺序调度：

1. 权威切片：一个可证伪命题、固定权威来源清单和停止条件。结果只分类为“已有唯一答案、权威冲突、权威未定义”，并提供精确位置和最小反例。
2. 实现观察切片：只在权威未定义或人类需要理解选择后果时启动，只读取与同一命题直接相关的实现和测试；实现现状不参与权威裁决。
3. 整合：负责该范围的调度者汇总命题状态。已有答案用于清除漂移；冲突或未定义项只形成供根级 Main 选择或询问用户的最小前沿。只有用户或父任务已在任务单/补充中明确授予负责该命题的上级对该命题的窄、具体决定权，且列明命名对象、允许结果、必须保持的不变量和执行条件时，该上级才可在范围内决定；否则只能向直接父级报告事实与前沿。

真正需要穷举时，先机械建立矩阵骨架，再把互不重叠的行分派给不同 agent；最后单独审查跨行接缝。每个 agent 只完成自己的闭合切片，不重复重建全局上下文。

#### 分片交接与边界

- 执行和独立评审各自使用专属任务单。初始任务单只包含一个命题、固定基线、该命题所需的权威摘录、验收条件和本切片 checkpoint 路径；不带入其他切片、全局调度资料或未授权结果。
- 初始任务单的命题、基线和已经发出的权威摘录不可变。执行计划可以在同一任务单中按序追加补充，但不得偷换命题或基线。发现任务单遗漏或错误时，追加更正并向当前执行者发送补充消息；每条补充原文保存在对应任务目录的 `main-{回合}.md`。
- 独立评审也沿专属任务单工作；需要额外事实时由负责该范围的调度者按同一文件和角色边界补充，不自行读取全局计划、其他切片或未授权结果。

#### 增量记录与上下文恢复

- 大型复审按可验证命题拆成小步骤，完成一个命题就写 checkpoint，不把证据和状态留到最后的总报告。
- checkpoint 是可恢复工作笔记，不只是进度元信息。每完成一个有边界的小步骤，记录已证事实、精确证据位置、事实如何支持或违反命题或不变量、被排除的解释或最小反例、未决项及其影响；重要结论不延迟到最终报告。
- 每个 checkpoint 至少有固定基线、已覆盖范围、权威来源、不变量、证据位置、结论、未决项和指向下一项命题或动作的 next_cursor。最终报告汇总这些笔记，不能替代它们；尚未核验的判断明确标为 pending。
- 发生上下文压缩、会话恢复或执行者更换时，先读取专属任务单和最大编号 checkpoint，再按下一动作继续。已记录的事实和证据不因压缩而丢弃，也不用摘要补全缺失内容。
- checkpoint 缺失或固定基线漂移时才重建该切片；其他情况下保持切片边界和已覆盖状态继续推进。
- 暴露、压缩或中断在完整执行并完成独立复审前，不是有效失败尝试。未覆盖或未决命题必须保留为未完成，不能当作通过。

#### 暴露、角色违规与弃用

- 只暴露共享路径或文件名时标记为“已暴露、未核实”，不自动推导污染或作废。只有确认实际读取、引用本切片外信息、越过角色边界，或影响无法排除时，才标记为“已污染、不可信”。
- 加载作用域内 AGENTS.md 或任务单明确禁止的 skill 是角色违规；立即停止并弃用该切片。禁止范围只限已经明确的 skill、文件或角色边界，不能扩展为一概禁止所有 skill 或协作工具。
- 用户决定直接弃用时，可重建的 worktree、分支、未提交 diff 和未采信产物在明确授权后删除。删除可能影响审计、法律合规、恢复、共享祖先或其他不可逆后果时，顾问只负责识别风险、固定证据和报告；不可逆清理由根级 Main 决定并执行。只有任务单或补充明确写明授权来源为用户或父任务、命名资源、允许动作、必须保持的不变量和执行条件时，指定的非根级角色才可在该窄范围内执行；顾问身份本身不构成删除决定或执行授权。未获上述明确窄授权时保留资源并向直接父级报告；不可重建的治理或审计记录保留并明确标记为弃用。

#### 模型选择边界

- 精确来源核对和局部实现观察是执行级事实核对的合适工作。
- 跨命题依赖、状态模型和最小决策前沿需要独立判断时，适合由思考级模型承担独立评审或顾问分析角色；新的执行切片仍按通用规则从执行级开始。
- 只有在相同、完整且稳定的切片上下文中形成有效失败后，才依据通用升级规则判断是否需要更高层级；宽任务无产出不是升级证据。

#### 完成判据

- 覆盖清单中的每个命题都有唯一状态和证据位置。
- 每个 subagent 产物只回答一个命题；旁支只登记所需上下文，不自行扩展。
- 权威来源已有答案时不启动运行时调查；代码和测试不会反向批准产品语义。
- 交给人类的前沿只包含会改变可观察行为且无法由现有权威唯一推出的选择。
