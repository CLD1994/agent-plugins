# Yuna 调度经验

本文件只保存本项目中有证据支持、能帮助以后切分任务或整理上下文的经验，以及已经完成的匿名模型比较摘要。任务规格、用户授权、通用调度规则和临时调度记录不属于本文件。

## 任务切分与上下文经验

### 权威分散的跨来源审查与规格收敛

- 适用任务特征：同一行为散落在历史规格、候选文档、实现和测试中；任务既要区分权威结论与实现观察，又要找出真正需要用户决定的边界。
- 观察事实：把全库发现、权威裁决、完整矩阵和综合决定放进一次宽委派后，执行者需要同时重建多类上下文，任务没有清楚的验收边界；提高模型层级不能修复不完整或混杂的任务说明。
- 采用的调度或上下文处理：先建立待判定命题和覆盖清单。每个权威核对切片只回答一个命题，并把结果归为“已有唯一答案、权威冲突、权威未定义”；只有后两类确需了解实现后果时，才另开实现观察切片。穷举矩阵由多个互不重叠的行切片完成，最后单独检查跨行接缝。
- 最终结果：权威事实、实现现状和用户决策被分开处理；规格完成收敛并合并到主线，未由现有权威决定的产品边界单独交给用户。
- 可复用结论：先按可证伪命题切分，再分别处理权威、实现和整合。每个执行者只接收当前命题、固定基线、直接相关来源和验收条件；实现现状不能反向批准产品语义。
- 边界和不能推出的结论：这条经验适用于权威来源分散、需要建立覆盖矩阵的审查，不能证明所有大型任务都应按命题拆分，也不能据此判断某个模型层级在其他任务中的能力。
