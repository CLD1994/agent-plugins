# 领域文档

本仓库采用 single-context 领域文档布局。工程 skills 在探索代码前按本文件读取领域术语和架构决策。

## 探索前读取

- 根目录 `CONTEXT.md`：领域词汇、对象边界和关键不变量
- `docs/adr/`：与当前工作范围有关的架构决策记录

文件不存在时继续当前工作，不把缺少文件本身作为问题，也不预先创建空文档。领域术语或决策实际形成后，由 `/domain-modeling` 按需创建或更新。

## 文件布局

```text
/
├── CONTEXT.md
├── docs/
│   └── adr/
│       ├── 0001-<decision>.md
│       └── 0002-<decision>.md
└── ...
```

## 使用领域词汇

issue 标题、spec、重构建议、测试名和代码说明应使用 `CONTEXT.md` 已定义的领域术语。

需要的概念尚未出现在 glossary 时，先判断它是与现有词汇重复，还是确实存在领域模型缺口。确认存在缺口后，把它交给 `/domain-modeling` 处理。

## 处理 ADR 冲突

输出与现有 ADR 冲突时，必须明确指出冲突及理由，不得静默覆盖已有决策。例如：

> 与 ADR-0007 的既有决策冲突；建议重新讨论，因为……
