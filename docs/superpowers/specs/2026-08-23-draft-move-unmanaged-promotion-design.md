# Draft move 未受管理操作数与提升设计

## 状态

状态：草案，待评审。

本规格不改变受管理页面命名空间的词法定义，不引入迁移专用命令，不增加平行
入口。它扩展 `move` 的操作数域与事实闭包，使候选根中的旧文件能够通过一条
命令完成"进入页面命名空间 + 全部可证明链接改写"的机械变换。

## 0. 与既有规格的关系

本规格是
[`2026-08-12-draft-candidate-root-incremental-migration-design.md`](./2026-08-12-draft-candidate-root-incremental-migration-design.md)
的后续修订，并同时修改
[`2026-08-10-draft-agent-cli-capabilities-design.md`](./2026-08-10-draft-agent-cli-capabilities-design.md)
中的操作数语法。发生冲突时，以本规格为准；未被下列事项改变的语义继续沿用：

- 2026-08-12 规格 §9.1 的 `move` 事实闭包行与 §9 典型行为中移动相关的条目，
  由本规格第 4 节取代；
- 2026-08-10 规格 §6"受管理页面参数必须解析为 Draft 内受管理页面"对
  `move` 的 `SOURCE` 增加本规格第 2 节的候选例外；`structure.unknown_page`
  仍是 `move` 的专用操作数错误码，语义按第 6 节精化；
- 2026-08-10 规格 §7 的词法命名空间（`index.md`、`conclusions.md`、
  `pages/**/*.md`）不变。`move` 不重新定义什么是页面；提升是文件因路径变更
  而进入命名空间的事实，链接身份继续按词法路径判定；
- 2026-08-12 规格 §8"命令的业务语义与根状态无关"继续成立：本规格只扩展
  `move` 的操作数域，不新增命令；`promote`、`collapse`、`trash`、`restore`、
  `status set`、`relation`、`query`、`check`、`adopt`、`recover` 全部不变；
- 2026-08-12 规格 §5（根状态与 marker）、§10（显式完整检查）、§11（查询
  完整性）、§12（adopt）不变。

## 1. 目标

旧文件进入候选根后，与链接有关的全部机械工作今天只能由 Agent 在 CLI 的锁、
操作日志、摘要复核和崩溃恢复保护之外手工完成，或者绕道"重建页面再粘贴"。
这与 2026-08-12 规格 §1 的目标直接冲突：链接重写是程序已经拥有的确定性能力，
却不对迁移场景最常见的操作数开放。

本规格的目标：

- `move` 接受未受管理的 `.md` 普通文件与目录作为来源，在候选根中一条命令
  完成提升与链接改写；
- 入站链接证明范围统一为根内全部 Markdown 文件，同时消除既有缺口：未受管理
  文件中指向受管理页面的入站链接，在移动该受管理页面时也被改写；
- 保持 2026-08-12 规格 §2.3 的全部不变量与 §15 的全部安全边界；候选放宽的
  仍然只是全局健康前置条件。

不在范围内：程序理解来源布局、自动识别页面、编码检测或转换、模式展开
（第 7、9 节）。

## 2. 命令表面与操作数分类

### 2.1 命令形态

```text
draft move SOURCE... TARGET
draft move --root ROOT SOURCE... TARGET
draft move SOURCE... TARGET --dry-run
```

- 至少一个 `SOURCE`，恰好一个 `TARGET`（最后一个位置参数）；
- `TARGET` 按词法分类，不做文件系统探测：后缀 `.md` 为文件目标；无 `.md`
  后缀为前缀目标；
- 文件目标要求恰好一个文件形 `SOURCE`；前缀目标允许一个或多个文件/目录
  `SOURCE`；
- 形态违例（文件目标配多个或目录 `SOURCE`、零个 `SOURCE`）是参数错误，
  退出码 2，发生在读取根内容之前，不创建内部状态；
- 单对 `move SOURCE TARGET`（文件来源 + 文件目标）与现行行为完全兼容；
- `--dry-run` 与正式执行使用同一闭包和同一最终不变量。

### 2.2 SOURCE 操作数分类

分类按以下顺序执行。分类不分支于 `root_state`；两种根状态的行为差异由门禁
次序保证（第 5 节）。

| 顺序 | SOURCE 路径事实 | 结果 |
|---|---|---|
| 1 | 绝对路径或含 `..` | `path.escape` |
| 2 | 落入 `.draft/` 内部协议领地 | `path.internal` |
| 3 | 符号链接 | `path.symlink_escape` |
| 4 | 目录 | 目录来源（§2.3 枚举） |
| 5 | 受管理页面 | 受管理文件来源（现行语义：叶页单移，枢纽连同子树） |
| 6 | 根内未受管理普通文件，后缀 `.md` | 未受管理文件来源 |
| 7 | 后缀非 `.md` | `path.not_markdown` |
| 8 | 不存在 / 其他非普通文件 | `structure.unknown_page` |

`path.internal` 的判定是词法的：第一个路径段为 `.draft`（根级内部协议
领地）即命中，先于任何文件系统探测。内容目录中恰好名为 `.draft` 的子目录
不属于内部领地，按普通内容处理。

`structure.unknown_page` 语义精化为：路径语法合法，但没有标识可移动单元。
可移动单元是受管理页面、未受管理的 `.md` 普通文件，或包含可移动内容的目录；
空枚举结果（§2.3）也落入此码。

### 2.3 目录 SOURCE 枚举

- 递归枚举目录下全部 `.md` 普通文件，稳定排序；
- 枚举遇到符号链接条目 → `path.symlink_escape`，`path` 为该条目的根内路径；
- 非 `.md` 内容不移动、原地留下；命令输出不报告留下清单，"只移动 `.md`、
  其余原地留下"由命令帮助文本与迁移参考文档说明；
- 枚举结果为空 → `structure.unknown_page`；
- `pages` 目录本身不是可移动单元 → `structure.protected`；
- 枚举只收集 `.md` 普通文件；遇到的符号链接条目拒绝整批
  （`path.symlink_escape`），非 `.md` 条目跳过并原地留下。枚举沿根内相对
  路径进行，不跟随符号链接，不产生越界路径。

语义分派按词法位置，不需要检查成员内容：按第 0 节的词法命名空间，`pages/`
下的目录其 `.md` 成员必然全部是受管理页面，`pages/` 外的目录其 `.md` 成员
必然全部未受管理，不存在混合目录。

- `pages/` 下的目录：复用现有路径重映射管线，机器块父声明维护、父导航重算、
  摘要复核照常。候选根中机器块父声明与物理位置不一致的脏页按物理语义移动，
  父声明重写为移动后的物理父页；无法重写的结果 → `structure.parent_mismatch`。
  `registered` 根的健康门禁保证这种分歧不存在；
- `pages/` 外的目录：逐成员执行第 3 节的提升语义，保持目录树结构。

### 2.4 前缀目标映射与结果校验

映射规则：

- 文件 `SOURCE`：结果 = `TARGET/<SOURCE 基名>`；
- 目录 `SOURCE`：结果 = `TARGET/<SOURCE 目录名>/<成员相对 SOURCE 的路径>`，
  目录自身名字作为第一级保留，与 `mv` 的追加语义一致。映射是纯词法拼接，
  不依赖目标位置的当前存在性，无歧义。

每个结果路径必须全部通过：

| 校验 | 错误码 |
|---|---|
| 前缀在 `pages/` 内（`pages` 或其真后代），结果随之在命名空间内 | `structure.invalid_target` |
| 不是既有受管理页面 | `structure.target_exists`，逐个点名 |
| 不落在本批任一目录来源内部 | `structure.descendant` |
| 不与本批其他结果碰撞 | `structure.conflict`，点名碰撞来源 |
| 父页占据（见下） | `structure.missing_parent` |

父页占据规则：结果的父路径必须由（a）可解析的受管理页面，或（b）本批同移
的文件在移动后占据。这是树形提升成立的关键：旧稿自带的目录内 `index.md` 与
子页同批移动时，子页结果的父路径在移动后存在；机器块欠账留给 `check`。

### 2.5 来源保护

根 `index.md` 与 `conclusions.md` 不得作为 `SOURCE`（`structure.protected`，
现行规则）。该保护按来源逐个适用；批量中任一来源命中即拒绝整批并点名。

## 3. 提升语义（未受管理来源）

`move` 对未受管理来源做三件事：

1. 文件字节迁往结果路径，复用同一套操作日志、暂存内容、摘要核对与崩溃
   恢复机制，无新机制；
2. 重算该文件内全部相对 CommonMark 链接到新基址；scheme 链接与锚点不变；
   指向留在原地的非 `.md` 资源（如图片）的链接同样按新基址重算；
3. 改写根内全部 Markdown 文件中指向本批移动前路径的入站链接（第 4 节
   闭包），每个链接者按自身位置重算相对形式。

`move` 对未受管理来源不做三件事：机器块、父关系、父导航。未受管理文件没有
机器块，这三项维护天然为空操作；提升后的页面资格语义只有"路径进入命名空间"，
协议欠账（缺机器块、缺标题、缺状态等）由 `check` 报告，由 Agent 在后续
修复。完整检查通过前 `adopt` 不可达，最终质量门禁不放宽。

候选迁移的典型序列：

```text
Agent: cp -r old/* ROOT/        # 来源零写入；复制是 Agent 的文件操作
draft move 00-background-and-evidence.md pages/00-background-and-evidence.md
draft move legacy-notes pages   # 整树提升为 pages/legacy-notes/...
draft check                     # 按诊断类别批量修复协议欠账
draft adopt
```

shell 通配（如 `*.md`）可用但非协议部分：根部通配会展开出 `index.md` 并命中
来源保护，命令点名拒绝整批，Agent 据此排除后重试（第 9 节）。

## 4. 统一事实闭包与最终不变量

本节取代 2026-08-12 规格 §9.1 的 `move` 行。该闭包只对 `move` 生效；其他
写命令的事实闭包不变（第 10 节）。

### 4.1 闭包

| 事实类 | 必须能够证明 |
|---|---|
| 来源事实 | 受管理页面完整（现行）；未受管理文件为普通文件、UTF-8 可解码、CommonMark 链接可提取；目录枚举成功且每个成员满足对应来源事实 |
| 目标事实 | §2.4 全部校验通过 |
| 入站引用可判定性 | 根内每一个 `.md` 普通文件（受管理页面 ∪ 未受管理文件，不含 `.draft/`）链接提取成功；提取出的链接逐一解析；凡目标等于移动集合中任一移动前路径者全部改写 |
| 子树事实 | 受管理子树（现行）；未受管理来源无子树概念 |

### 4.2 拒绝行

任一 Markdown 文件链接不可判定——字节不可解码，或链接源文本与渲染结果对齐
失败——拒绝：`structure.dirty`，`details` 为稳定排序后的阻碍路径全集。阻碍
集合把不可解析的受管理页面与不可判定的未受管理 `.md` 文件合并为同一个集合。
拒绝不创建操作日志、不产生部分写入。

阻碍清单同时是修复清单：不可解码文件由 Agent 先行转码（第 7 节），对齐失败
文件由 Agent 修正写法，然后重试。

### 4.3 最终不变量

- 无目标冲突、无路径逃逸、不移入保护路径、结果不落入来源目录内部；
- 路径、父关系、父导航和全部可受影响链接一致：未受管理来源的父关系与父导航
  为空操作，链接一致性由闭包证明；受管理来源沿用现行维护与证明；
- 空枢纽检查只对受管理内容移动适用；
- 提交前校验：计划中全部输入摘要与读取时一致；本命令创建或改写的文件仍可被
  对应解析器读取——对未受管理来源，该项为**链接可提取**，不是整页协议可
  解析。

### 4.4 典型行为

- 根部旧稿含相对链接，一条命令提升，旧稿内链接与全根入站链接一并改写；
- 移动受管理页面时，未受管理文件中指向它的入站链接同样被改写；
- 根内残留 GBK 等非 UTF-8 旧稿时，任何 `move` 被拒绝并点名该文件；转码后
  重试；
- 提升不符合页面协议的文件成功，`check` 报告其欠账；`adopt` 仍要求全绿；
- 目录提升后，非 `.md` 内容原地留下，由 Agent 自行清理；
- 候选命令成功后允许根内仍存在与本命令无关的检查错误（沿用 2026-08-12 §9）。

## 5. 两种根状态的差异来源

分类与闭包的表述与 `root_state` 无关。行为差异来自既有门禁次序：`move` 在
操作数分类之前执行事实加载——`registered` 为全绿健康门禁，`candidate` 为
阻碍检查。`registered` 根中未受管理 `.md` 文件本身是检查错误，健康门禁必然
先行拒绝，因此未受管理来源分类与扩展闭包在 `registered` 下不可达，无需任何
新分支。

候选根采用操作级门禁：不可判定文件的拒绝是本操作的事实闭包要求（无法证明
没有相关引用），不是全局健康要求。2026-08-12 规格 §2.4"候选允许积累全局
协议错误"不变。

## 6. 错误码

新码与精化语义登记在生产代码的单一错误码权威来源，CLI、渲染器、测试和文档
从该来源引用：

| 代码 | `path` | `details` |
|---|---|---|
| `path.internal`（新增） | 规范化后的操作数根内 POSIX 相对路径 | 空 |
| `structure.unknown_page`（语义精化，§2.2） | 操作数 | 空 |
| `structure.dirty`（阻碍集合扩展，§4.2） | 根 | 稳定排序后的阻碍路径全集 |
| `path.symlink_escape`（扩展到枚举条目） | 操作数或枚举条目根内路径 | 沿用现状 |
| `structure.protected`（扩展到 `pages` 目录来源） | 来源 | 沿用现状 |

`structure.invalid_target`、`structure.target_exists`、`structure.conflict`、
`structure.missing_parent`、`structure.descendant`、`structure.parent_mismatch`、
`path.escape`、`path.not_markdown` 沿用现行语义。

参数形态错误不是检查码：退出码 2，先于根内容读取（2026-08-12 规格 §10 的
参数错误先例）。

## 7. 编码协议

- CLI 保持严格 UTF-8 字节协议。字节保真重写、摘要、恢复机制与机器块的确定
  解析都以单一规范编码为前提；编码检测是启发式判断，不得引入；
- 非 UTF-8 的 `.md` 文件是不可判定事实，按 §4.2 成为阻碍，不被静默跳过、
  猜测或转换；
- 转码是 Agent 工作流步骤：建立候选页面前把旧稿转为 UTF-8。现成手段包括
  `iconv` 与标准库 `gb18030` 等；CLI 不提供编码参数、检测或转换；
- 本条不改变 `check` 对受管理页面解析失败的现行报告。

## 8. 链接定义

- 链接 = CommonMark 链接：内联链接、有定义的引用链接、带 scheme 的自动
  链接、图片。这是现有提取器的既有定义，本规格不改变它；
- 未定义的引用形式 `[文本][标签]`、尖括号裸路径等按 CommonMark 不是链接，
  不在改写范围。它们不是起作用的链接，不因移动而损坏；
- 目标含反斜杠转义或 HTML 实体会造成源文本对齐失败，该文件按不可判定拒绝
  （§4.2）；该现状不在本次修订中改变。

## 9. 平台与模式展开

- CLI 不做模式展开。`*.md` 等通配是调用方 shell 的职责；
- bash 与 PowerShell 原生展开；不展开的环境（如 cmd.exe）中模式字面量到达
  CLI，收到 `structure.unknown_page`，Agent 改用显式枚举；
- 平台行为差异写入技能与迁移参考文档；
- 页面路径语法继续使用 `/`，与操作系统无关。

## 10. 不变的交互

- 生命周期：`move` 是业务写命令，受管根恰好推进一次（2026-08-12 §8.1）；
- `recover`：提升与树形移动在日志中是普通的写入/删除变更集，前向完成与
  回滚复用现行统一恢复状态机；
- `adopt`：完整检查全绿门禁不变；观察清单已覆盖未受管理文件（目录成员集合、
  类型与摘要）；
- `check`：提升后该文件的 `page.unmanaged_path` 消失，出现 `page.*` 协议
  诊断；其他未受管理文件照常报告；
- `promote`、`collapse`、`trash`、`restore`、`status set`、`relation`、
  `query` 的事实闭包与行为全部不变。

## 11. 测试设计

### 11.1 单元测试

同进程、无真实文件系统，替身受真实接口约束：

- `SOURCE` 分类决策表逐行：§2.2 顺序 1—8，含 `.draft/` 词法判定先于文件系统
  探测、目录与符号链接的次序边界；
- 参数形态错误退出码 2：文件目标配多个来源、文件目标配目录来源、零来源；
- 前缀映射算术：文件取基名、目录取完整路径；`pages/` 命名空间约束；
  `target_exists`、`conflict`、`descendant`、`missing_parent` 逐类点名；
- 父页占据泛化：同批文件占据通过；父路径无人占据拒绝；
- 目录枚举：符号链接条目拒绝整批、空枚举 `structure.unknown_page`、
  `pages` 本身 `structure.protected`、非 `.md` 条目跳过；
- 阻碍集合扩展：不可解码未受管理文件、不可解析受管理页面、两者并存进入
  `structure.dirty` 的排序 `details`；该扩展只对 `move` 生效，其他命令闭包
  不变；
- 出站重算：相对链接按新基址重表达；scheme 链接与锚点不变；指向留下图片的
  链接重算正确；
- 入站改写：受管理页面与未受管理文件两类链接者各按自身位置重算；同批移动
  集合内部交叉链接正确重映射；
- 提交前校验对未受管理来源按链接可提取判定；
- `--dry-run` 与正式执行同闭包同不变量；
- `pages/` 下目录来源：父声明重写为移动后物理父页；父声明分歧无法重写时
  `structure.parent_mismatch`；良构根上与现行枢纽子树移动结果一致。

### 11.2 集成测试

真实文件系统单独覆盖：

- 端到端提升：根部旧稿（含相对链接）+ 一个受管理页面链向它 + 另一个未受
  管理文件链向它 → 移动后三类引用全部改写、文件就位、无机器块；
- 树形提升：遗留目录（多级、含 `index.md` 的枢纽形状、含图片）复制进根后
  一条命令提升 → 树结构保持、图片原地留下、指向图片的出站链接正确；
- 提升后 `check` 报告该文件的 `page.*` 诊断、不再报告其 `page.unmanaged_path`；
- 根内存在 GBK 文件 → `move` 拒绝并点名，全部文件字节不变；
- 移动中途注入中断 → `recover` 恢复原始字节与路径；
- `registered` 根：未受管理文件使健康门禁先行拒绝，不进入操作数分类；
- `--dry-run` 输出与正式执行变更集一致；
- `adopt` 全绿门禁不受影响；来源目录在迁移前后摘要一致（沿用 2026-08-12
  §16.2 的来源零写入验证）。

### 11.3 完整质量门禁

实施完成前运行与变更范围相称的核心单元测试、核心集成测试、适配层测试、严格
类型检查和格式检查。核心与适配层测试分开运行；网络集成测试如未运行须如实
记录。

## 12. 未决事项

1. 其他承担链接改写职责的命令（`promote`、`collapse`、`trash` 等）对未受
   管理文件的入站链接仍存在同类缺口；是否统一到本闭包，在本规格落地后另行
   立项；
2. 没有 CLI 命令能为已有受管理页面补初始机器块：提升后 Agent 只能手写机器
   块（2026-08-12 规格 §4.3 容忍结构合法的手工机器块作为当前文件事实）或
   重建页面。是否新增命令是后续议题；
3. 反斜杠转义与 HTML 实体目标的源对齐失败维持罕见拒绝现状；
4. Windows 平台的展开行为由文档覆盖，CLI 不感知。

## 13. 预计实现影响（非硬性文件清单）

以下是根据当前代码结构作出的实现预估，不限制实施者在保持行为契约的前提下
调整模块边界：

- 操作事实加载为 `move` 扩充阻碍集合：枚举根内全部 `.md` 普通文件，不可
  解码或链接提取失败者并入阻碍；该扩充只对 `move` 的闭包生效，不改变其他
  命令的事实加载；
- 结构规划：操作数分类双类型化、目录枚举、前缀映射、泛化父页占据、未受
  管理成员的轻语义计划生成；受管理目录来源复用现有路径重映射管线；
- CLI：`move` 参数形态改为 `SOURCE... TARGET`，形态违例退出码 2；帮助文本
  写明"只移动 `.md`，其余原地留下"；
- 错误码权威来源：登记 `path.internal`，精化 `structure.unknown_page`，
  扩展 `structure.dirty` 阻碍约定；
- 技能与迁移参考文档：转码步骤、平台展开行为、树形迁移示例、`*.md` 命中
  来源保护的重试模式。
