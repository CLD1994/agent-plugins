# Draft v1 领域合同 Standards Review

结论：FAIL；7 个 finding（6 个 hard violation，1 个 judgement call）。范围：B0 `ca33c9f28bbeca9055c462ef1f10d5f4596cf73b` 到候选 `04726b218ec5ab7f47b6eae43b8e597f0f484cfa` 的三份变更文件；`CONTEXT.md` 新增项本身保持 glossary 形式。Hard 依据为 `AGENTS.md` 的规格/计划（输入、输出、失败、决策表）及架构（显式状态、单一权威）规则。

## F1 — High / hard：受保护路径与 hub 路径冲突

- 位置：`domain-contract.md:43-58, 203-248`。
- 触发：`pages/x/index.md` 是可移动 hub 且是 `collapse` 输入，但“`index.md` 不能作为 source”又拒绝它；同一规则还会误伤合法叶页 `pages/index.md`。
- 规则/根因：`AGENTS.md` 要求命名准确、合同可执行；basename 规则与路径角色不一致。
- 修复：只保护根 `index.md` 与根 `conclusions.md`，明确 hub `pages/<name>/index.md`、叶页 `pages/index.md` 的 source 矩阵。
- 影响/验证：move、promote、collapse、Trash；覆盖 root/hub/leaf 三类的 accept/reject 场景。
- 未核验：若确实要全局保留 basename，必须显式声明并定义这些页面不可用。

## F2 — High / hard：`ResourceIdentity` 混入会变化的观测状态

- 位置：`domain-contract.md:115-134, 360-368`。
- 触发：缺失目标后来出现（或 unavailable 恢复）时 `target_state` 改变，但文档又要求 identity 由词法位置稳定决定，且 Backlinks 接受不存在的 target。
- 规则/根因：`AGENTS.md` 要求显式建模不同状态；稳定身份与观察事实被放进同一概念。
- 修复：定义精确的稳定 `ResourceIdentity`（kind/scope/规范词法目标），另定义 `ResourceObservation.target_state`；重写表、去重和 backlink 规则。
- 影响/验证：Links、Backlinks、闭包、move 映射；测试 missing→present、unavailable→present 及 page-admission。
- 未核验：`target_state` 是否原意仅为事实字段；当前文字没有说明。

## F3 — High / hard：生成结论页可破坏 superseded 不变量

- 位置：`domain-contract.md:76, 256-290`。
- 触发：`relation.add(supersedes, ..., conclusions.md)` 将目标设为 `superseded` 并写 `superseded_by`；下一次生成无条件把结论页设为 `proposed`，不清除关系。
- 规则/根因：`AGENTS.md` 的状态不变量要求可执行；文档同时要求 `superseded ⇔ superseded_by≥1`，跨命令状态转换未闭合。
- 修复：禁止结论页成为 supersedes target，或让 generate/status/relation 共用生成页状态—关系决策表并原子维护配对。
- 影响/验证：status、relation、generate、Check/adopt；覆盖目标为 generated conclusions 的 add、remove、generate 顺序。
- 未核验：未找到“结论页不可作为关系 target”的既有条款。

## F4 — Medium / hard：完整集合规则与 partial read 自相矛盾

- 位置：`domain-contract.md:182-186, 353-385`。
- 触发：候选根存在不可解析的无关页时，`Backlinks`/incoming `Relations`/`Status` 允许 `complete=false` 成功；§4.2 又称任何需完整集合的命令必须完整返回或整体失败。
- 规则/根因：`AGENTS.md` 要求输入、输出和失败语义可执行；这里未分层，调用方无法据合同判定读例外。
- 修复：把 §4.2 限定为写/计划，或增加封闭的 read-exception 表并规定 total/blocking/truncation 语义；保持 partial 不可证明否定。
- 影响/验证：候选/正式根的所有集合读取；逐项验证 malformed unrelated page、空页和 count-only。
- 未核验：§4.2 是否只想约束写命令，原文未限定。

## F5 — Medium / hard：关系 add/remove 缺少完整决策模型

- 位置：`domain-contract.md:91-93, 267-275`。
- 触发：单侧 `supersedes` 残留、目标状态已与关系不一致、或删除最后一条反向关系时，幂等清理与“必须提供新状态”没有优先级/组合表。
- 规则/根因：`AGENTS.md` 要求多条件行为用完整决策表/状态模型；当前 bullet 不能决定零写、补齐或拒绝。
- 修复：按 operation(add/remove)×relation code×正反侧存在×目标状态×new-state 建表，定义所有非法组合及原子失败。
- 影响/验证：三种关系代码及 status invariant；穷举矩阵并验证环、残留和幂等。
- 未核验：关系单侧损坏是否应视为 corrupt 或可修复。

## F6 — Medium / hard：状态说明的 required/optional 语义冲突

- 位置：`domain-contract.md:74, 105, 192, 254-256, 290`。
- 触发：状态说明被称为非空且空值非法，但 create 没有说明输入，status 又允许 clear，生成器固定形状也未规定说明。
- 规则/根因：`AGENTS.md` 要求输入、输出和不变量可执行；同一状态字段不能同时要求存在又允许删除。
- 修复：若 required，补齐 create/generate 输入并禁止 clear；若 optional，明确“省略合法，仅显式空说明非法”。
- 影响/验证：create、status、generate、Check；测试省略、空字符串、清除和生成页。
- 未核验：`可追加说明` 是否意图表达 optional。

## F7 — Medium / judgement call：非 runtime 合同仍泄漏私有边界

- 位置：`domain-contract.md:7-11, 51, 182-184, 320-322, 344, 393, 406, 409`。
- 触发：声明“非 runtime/不定义内部机制”后仍把 `.draft/`、runtime artifact、admission、accepted handoff、notification/recover、runtime error 作为规范术语。
- 规则/根因：层次与权威边界不清；可能形成 Divergent Change/Mysterious Name（smell baseline 仅为判断意见）。
- 修复：领域合同只保留可观察的 root/page/resource/Trash 事实；runtime admission、artifact、handoff、恢复和错误映射集中到 foundation spec，并用单一边界引用连接。
- 影响/验证：领域合同与 foundation spec 的交叉引用/冲突审计；确认实现变更无需改领域文档。
- 未核验：这些 runtime 名称是否已被批准为公共可观察协议，而非私有实现。

## 复杂度判断与执行计划

需要执行计划：F1/F2/F3/F4/F5/F6 横跨状态机、多个命令和读写接缝。顺序：先冻结受保护路径与 identity/observation 类型；再补关系、生成页、read completeness 和说明决策表；随后补每命令 input/output/error/recovery 矩阵并清理 runtime 边界。门禁：无矛盾路径分类；identity 在目标出现/消失时稳定；所有 superseded 配对成立；partial read 不伪造否定；所有状态/关系组合有零写或明确转换；Markdown/术语审计确认 `CONTEXT.md` 仍为 glossary。
