# 07 Lifecycle、read、notification 与 CLI adapter

Status: ready-for-human

Blocked by: 01, 02, 03, 04, 05, 06

## 确认合同

实施 spec 第 2、6、8、11 节。CLI 的 `init` 路由只规范化显式 init root，直接调用不经 RuntimeFactory 构造的公开 `Lifecycle.initialize`；不读取 cwd/env 选择 root，也不要求 root 已有 marker。其他受管理根命令按既定优先级选择规范绝对 root，再且仅通过 `RuntimeFactory.for_root(AbsoluteRoot)` 获取 root-bound `OperationRuntime`；factory 不返回或承诺 Lifecycle，CLI 不得接触 `RuntimeDeps` 或其他内部协作者。CLI、插件适配层生产代码及插件适配层 unit/integration tests 对抽象或 concrete `HandoffAdapter` 的导入均为零，插件适配层不得导入核心 draft 包。只有 OperationRuntime read 提供 Check/Page/Links/Backlinks/Relations/Status/Recoverable。read 的稳定 preflight/final projection 不取得 OS root lock；仅自动 AdvanceDue，或 Page/Backlinks/Check 的机会式 index maintenance 子阶段才尝试取得 stable lock，live 时按既有 busy 规则跳过子阶段并带 warning 继续稳定 projection。有效记录无 live owner、marker/runtime/descriptor 匹配且仍有 InitDescriptor cleanup artifacts，或 corrupt 时，read/Check admission 返回错误且无 projection。九类 CLI 命令映射支持 `Execute`/`DryRun`；init、adopt、restore、recover、notification 不支持 DryRun。DryRun 无已发现记录时不 probe OS lock，成功返回 point-in-time plan/outcome 且零副作用；已发现记录后按 live owner、无 live owner、消失和 corrupt 分区投影。notification 只调用 `maintain(ExternalFilesChanged)`：有效运行期根锁记录无 live owner，或 marker/runtime/descriptor 匹配、无记录但仍有 InitDescriptor cleanup artifacts 时，均返回 `runtime.recovery_required` error、退出码 3 且不带 `delivered`。后者不得取得用于恢复的 stable lock、发布 record、调用 `recover()`/AdvanceDue/index maintenance 或清理 artifacts，目录字节保持不变；只有 maintain 的 live busy，以及 stable authority 仍可认证时 external-change 的表定分支映射为最小 delivered。`delivered:true` 不泄漏内部状态。

## 建议实现与顺序

1. 先写 adapter 失败 unit tests：根选择、高优先级无效不回退、互斥接口路由、结果投影、exit code、notification 最小响应。完成条件：`Lifecycle.initialize` 直达、各 read、maintain、recover、ordinary Execute、`adopt` Execute 及支持 DryRun 的 `perform` 八类请求和 `trash` 路由恰与 spec §6 一致；除 initialize 外的 OperationRuntime 六方法均由 `RuntimeFactory.for_root` 返回实例调用，factory 返回类型不含 Lifecycle；notification 输出逐行匹配 spec 第 11 节表，stale record 与 cleanup remnants 的 recovery-required、corrupt、durability failure 和未满足 stable-authority 条件的 external-change error 行均没有 `delivered`，live busy 与可认证 external-change 行保持最小 delivered；证据为 adapter unit 输出。
2. 写 Windows/macOS/Linux integration 与 fault matrix：init 直达 Lifecycle.initialize 且不经过 factory、不读取 cwd/env、不要求 marker；其他命令按 root 优先级选择并经 RuntimeFactory 取得 OperationRuntime；read/DryRun 零副作用、Page backlink 最终全扫描、无记录 DryRun 不 probe、已发现记录 try-lock live/无 live owner/消失/corrupt、read/Check 稳定 projection 无锁、AdvanceDue 与 Page/Backlinks/Check 机会维护的 stable lock、live busy skip/warning、external change 分类、check active 深检、notification 只经 maintain 无恢复/生命周期。完成条件：每个 ReadRequest 覆盖 preflight/automatic/final 三阶段，成功 DryRun 返回 plan/outcome 且树字节不变，不创建 record/operation/epoch/artifact；try-lock 失败为 busy，成功后同一有效记录返回 recovery-required，记录消失后的单次重新 admission 再次变化为 external-change；有效记录无 live owner、cleanup remnants 或 corrupt 时 read/Check 无 projection；busy 或机会维护竞争时跳过自动写并带 warning 返回稳定 projection；notification 对 stale record 与 marker-ready cleanup remnants 均返回 recovery-required、退出码 3、无 delivered，且后者零 stable-lock/record/recover/AdvanceDue/index-maintenance/cleanup、目录字节不变；corrupt、durability failure 与 external-change 的 maintain admission 投影分别按 spec 第 11 节审计，只有 live busy 和可认证 external-change 保持 delivered；各失败分支均不产生 DryRun plan；缺失/过期 schedule 或 recovery-required 的 Page/Status 自动步骤为 0 candidate/0 handoff；deadline 前后未新建 attempt 的 failed/unknown 均零 warning 重播；证据为按平台 scan generation/token trace 与 fault matrix 输出。
3. 实现 CLI composition、read projection 与 notification adapter；按 core/adapter 四类测试树分别运行。完成条件：四个测试树分别通过，CLI init 仅调用公开 `Lifecycle.initialize`，其他命令仅通过 `RuntimeFactory.for_root(AbsoluteRoot)` 获取 `OperationRuntime`，CLI/插件适配层生产代码及插件适配层 unit/integration tests 对抽象或 concrete `HandoffAdapter` 的导入均为零，插件适配层不得导入核心 draft 包；核心 runtime unit/integration tests 不得导入 concrete local HandoffAdapter、`RuntimeDeps`、`PlatformAdapter` concrete implementations、worker、Clock/ID concrete sources、运行期根锁、recovery、index-settled 或其他内部协作者，隔离 handoff 时仅可引用抽象 `HandoffAdapter` Interface 并使用受真实 Interface 约束的 mock/fake；三平台 integration 通过公开行为 Interface 使用内部装配的真实本地 concrete Adapter；无 private runtime import 或其他内部协作者导入；factory 不返回或承诺 Lifecycle；notification 不泄露 routine 内部状态；证据为四条命令输出与 AST/import/export 审计。

## 禁止捷径与完成标准

不得让 CLI 读 runtime 文件、调用 internal seam、无条件提前推进、从 notification 调用 read/recover，或把 live busy 与 recovery-required 折叠。完成时常规成功不泄漏 routine lifecycle，错误最多含一个有序 lifecycle result 与本次新 warning；三平台输出和退出码矩阵全部可复验。
