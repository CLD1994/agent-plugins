# 审查机器合同的端到端闭合

Type: prototype

Blocked by: 15 冻结 composition 与 deterministic fault seam

本文是过程审计证据，不是行为 authority。当前行为只由 `plugins/draft/docs/spec/` 下的正式 owner 页面定义；`.scratch` foundation、wayfinding 与本 issue 只记录 tracker、provenance 或闭合诊断，不能补出未签行为。

## Question

把已批准的领域合同、公共协议、状态/所有权模型、平台合同、时间/ID、canonical encoding、所有 durable schema、Handoff 协议和测试 seam 连成端到端控制流后，是否每个入口都从权威输入经过派生、副作用、失败、重试和恢复到达唯一可观察结果？是否还存在重复 authority、未定义状态、循环依赖、不可故障注入的分支或需要执行者自行选择的行为；哪些结论应进入 ADR、spec、总控计划或执行 ticket？

### 跨页闭合待决项

下列接缝必须在正式 spec 中补齐、更新 provenance 与消费者并获得所需 signer 批准后，才可移除 `unresolved`。如需记录取舍，ADR 只能解释理由，不得定义或覆盖行为。

1. `unresolved`: 领域请求（create/move/promote/collapse/status/relation/generate-conclusions/adopt）到 operation `manifest`/`progress`、content、catalog/head 和最终 `Outcome` 的统一 correlation/id 绑定未定义。
2. `unresolved`: 页面字节、机器区、关系和 `conclusions.md` 快照到 runtime content authority/head epoch 的原子提交边界及崩溃后的唯一结果未定义。
3. `unresolved`: `read` 自动 lifecycle 后最终重读、snapshot token、projection warning 与 `ReadOutcome` 字段的统一合同未定义。
4. `unresolved`: `notification` 的 adapter 入口、maintain 错误到退出码/重试调度的映射未定义；不得以 `delivered` 覆盖错误。
5. `unresolved`: Trash/Restore 页面包、handoff receipt/attempt、catalog membership 的精确成员、排序和清理授权边界未定义。
6. `unresolved`: move/promote/collapse 共享 mapping 的 manifest 编码、`changed_paths` 字段/排序、自动 collapse 触发与同批提交边界未定义。
7. `unresolved`: promote 与 move 的共享 mapping/result/lifecycle 结果接口，以及跨入口失败、重试和恢复的统一投影未定义。
8. `unresolved`: recover 前向/回滚/cleanup 的选择判定、`RecoveryOutcome` 机器字段和重复 recover 的幂等公开语义未定义。
